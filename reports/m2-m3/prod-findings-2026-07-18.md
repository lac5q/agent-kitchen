## Actionable bugs

### 1. mem0 Qdrant-recovery loop (HIGH)

- File: `services/memory/mem0-server.py`, function `_qdrant_health_checker`
- Symptom: prod journal showed 87 "Auto-reset memory client after Qdrant
  recovery (in-process)" log lines in 4 hours, paired with the same number
  of "Resetting Mem0 Memory instance (Qdrant recovery)" lines.
- Root cause: the health checker called `reset_memory()` unconditionally
  every 60s once Qdrant had been healthy for 3 consecutive ticks. Combined
  with the lazy-reinit path in `get_memory()`, this produced a thrashing
  loop: reset -> next API request lazily re-inits -> health checker sees
  a healthy client and resets again after the threshold elapses.
- Fix: guard the reset with `if _memory is None or _init_error is not
  None`. The reset only fires when the in-process client is actually
  broken; otherwise log a debug-level skip.
- Branch: `hotfix/mem0-qdrant-recovery-loop` (commit `89565e8d`)
- Risk: low. Same reset path is still taken in the failure case; the only
  behavioral change is suppressing redundant resets.
- Validation: Python AST parse passes. No unit test exists for this
  background loop. Verification will be observed in prod journal after
  the patch is deployed: the 3-minute "Auto-reset" cadence should drop
  to zero unless Qdrant actually goes down.

### 2. Consolidation LLM JSON parse failures (MEDIUM)

- File: `apps/memroos/src/lib/memory-consolidation.ts`
- Symptom: 7 "[consolidation] Failed to parse LLM response as JSON --
  writing run with 0 insights" errors today, each silently discarding
  the batch's insights.
- Root cause: small local chat models often wrap their JSON output in
  prose ("Here are the insights: [...]") and rarely fence it. The parser
  only stripped markdown fences and called `JSON.parse(cleanedText)`;
  prose-wrapped JSON throws.
- Fix: walk the cleaned text, find the first balanced `[` ... `]` while
  tracking strings and escapes so embedded brackets do not desync, and
  parse that slice. Fall back to the cleaned text when no bracket pair
  is present. Add a warn log when the response parses but is not an
  array, and a 200-char preview in the catch block for future debugging.
- Branch: `hotfix/consolidation-llm-json-extract` (commit `3b6f86e4`)
- Risk: low. Schema validation is unchanged; insight filtering still
  requires the same fields and `ALLOWED_INSIGHT_TYPES` membership.
- Validation: `npm run typecheck` clean. Targeted tests
  (`memory-recall-evals.test.ts`, `memory-recall-canary-ci.test.ts`) pass.
  No test file exists for `memory-consolidation.ts` itself; verification
  in prod is "wait for the next consolidation run and confirm insights
  are written".
