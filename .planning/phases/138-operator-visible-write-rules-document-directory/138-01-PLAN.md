# 138-01 Plan: Operator-Visible Write Rules + Document Directory

## Objective

1. **WRITERULES-01**: Each space has a declarative "Write Rules" table (data type -> target document/resource) editable in the operator UI.
2. **WRITERULES-02**: The agent's memory adapter consults the Write Rules table before routing a save; mismatches are surfaced as receipts, not silently re-routed.
3. **WRITERULES-03**: Each space has a Document Directory (name + purpose + resource/artifact id) editable in the operator UI.
4. **WRITERULES-04**: Write Rules + Document Directory changes ship in the run ledger so the agent's view stays in sync; stale rules trigger a drift receipt.
5. **WRITERULES-05**: Operator edits are versioned + locked (optimistic concurrency); concurrent agent writes during an edit either wait or fail with a policy receipt.
6. **WRITERULES-06**: Write Rules are schema-validated (data type, target document, fallback rule); invalid rules rejected at edit time with structured error.

## Design

### Schema: v7 migration — `write_rules` + `document_directory` tables

**`write_rules` table:**
- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE`
- `data_type TEXT NOT NULL` (e.g. "transcript", "meeting_note", "code", "research")
- `target_document TEXT NOT NULL` (document/resource name the data type routes to)
- `fallback_rule TEXT NOT NULL DEFAULT 'reject' CHECK(fallback_rule IN ('reject','default_doc'))`
- `version INTEGER NOT NULL DEFAULT 1` (optimistic locking)
- `created_by TEXT NOT NULL`
- `created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))`
- `updated_at TEXT`
- `updated_by TEXT`
- Unique index on `(space_id, data_type)`

**`document_directory` table:**
- `id INTEGER PRIMARY KEY AUTOINCREMENT`
- `space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE`
- `name TEXT NOT NULL` (document name)
- `purpose TEXT` (what this document is for)
- `resource_id TEXT` (artifact/resource id)
- `version INTEGER NOT NULL DEFAULT 1` (optimistic locking)
- `created_by TEXT NOT NULL`
- `created_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))`
- `updated_at TEXT`
- `updated_by TEXT`
- Unique index on `(space_id, name)`

### `apps/memroos/src/lib/write-rules.ts` — NEW

```ts
export interface WriteRule {
  id: number;
  spaceId: string;
  dataType: string;
  targetDocument: string;
  fallbackRule: "reject" | "default_doc";
  version: number;
  createdBy: string;
  createdAt: string;
  updatedAt: string | null;
  updatedBy: string | null;
}

export interface DocumentDirectoryEntry {
  id: number;
  spaceId: string;
  name: string;
  purpose: string | null;
  resourceId: string | null;
  version: number;
  createdBy: string;
  createdAt: string;
  updatedAt: string | null;
  updatedBy: string | null;
}

// Schema validation (WRITERULES-06)
export function validateWriteRule(input: { dataType: string; targetDocument: string; fallbackRule?: string }): { valid: boolean; errors: string[] };

// WRITERULES-01: Create a write rule
export function createWriteRule(db, input: { spaceId: string; dataType: string; targetDocument: string; fallbackRule?: string; actorId: string }): WriteRule;

// Get all write rules for a space
export function getWriteRules(db, spaceId: string): WriteRule[];

// WRITERULES-05: Update with optimistic locking — throws if version mismatch
export function updateWriteRule(db, ruleId: number, input: { targetDocument?: string; fallbackRule?: string; actorId: string; expectedVersion: number }): WriteRule;

// WRITERULES-05: Delete with optimistic locking
export function deleteWriteRule(db, ruleId: number, input: { actorId: string; expectedVersion: number }): void;

// WRITERULES-02: Consult write rules before routing a save
export function resolveWriteTarget(db, spaceId: string, dataType: string): { matched: boolean; targetDocument: string | null; receiptReason: string };

// WRITERULES-03: Document Directory CRUD
export function createDocumentDirectoryEntry(db, input: { spaceId: string; name: string; purpose?: string; resourceId?: string; actorId: string }): DocumentDirectoryEntry;
export function getDocumentDirectory(db, spaceId: string): DocumentDirectoryEntry[];
export function updateDocumentDirectoryEntry(db, entryId: number, input: { name?: string; purpose?: string; resourceId?: string; actorId: string; expectedVersion: number }): DocumentDirectoryEntry;
export function deleteDocumentDirectoryEntry(db, entryId: number, input: { actorId: string; expectedVersion: number }): void;

// WRITERULES-04: Check if agent's view of rules is stale
export function checkWriteRuleDrift(db, spaceId: string, agentKnownVersion: number): { isStale: boolean; currentVersion: number; driftReceiptReason: string };
```

### Run ledger integration (WRITERULES-04)
- All CRUD operations write `audit_entries` with event types `write_rule.created`, `write_rule.updated`, `write_rule.deleted`, `document_dir.created`, `document_dir.updated`, `document_dir.deleted`.
- `resolveWriteTarget` writes a `write_rule.mismatch` audit entry when no rule matches and fallback is 'reject'.
- `checkWriteRuleDrift` returns drift info; caller writes a `write_rule.drift` audit entry if stale.

### Optimistic locking (WRITERULES-05)
- `updateWriteRule` and `deleteWriteRule` accept `expectedVersion`. If the current DB version != expectedVersion, throw `Error("write rule version conflict: expected X, found Y")`.
- Same pattern for document directory entries.
- All updates increment `version` by 1.
