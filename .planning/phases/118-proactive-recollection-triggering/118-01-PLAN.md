# 118-01 Plan: Proactive Recollection Triggering

## Objective

Make MemRoOS decide when an agent needs memory before work starts, before tools run, or before a final answer, without relying on Luis to say "search memory." The result should be an auditable recollection decision that either searches and injects context or records why search was skipped.

## Scope

- Add a deterministic recollection trigger policy for task text, entities, recency language, source refs, active project, handoff state, rediscovery risk, and required timing.
- Add a bounded query planner that emits tier-aware recall queries with explicit project/source scope.
- Add a candidate scorer that blends semantic/lexical relevance, recency, salience/importance, source freshness, prior usefulness, and policy-risk penalties.
- Add context-pack assembly that injects only threshold-cleared memories and records ignored/skipped candidates.
- Write recollection receipts into memory traces and NOC efficiency telemetry.
- Extend recall evals with proactive timing cases and negative fixtures for noisy recency.

## Non-Goals

- No new memory backend.
- No replacement of mem0, Qdrant, Neo4j, SQLite, qmd, or GitNexus.
- No automatic cross-project recall without explicit allowlist and policy proof.
- No storing raw sensitive payloads in recollection receipts.
- No LLM-only hidden trigger decision; any LLM assist must produce typed evidence consumed by deterministic policy.

## Design Contract

### Trigger Decision

The recollection policy returns:

```json
{
  "decision": "search_required",
  "timing": "before_plan",
  "reasons": ["task_has_recent_ref", "project_has_recent_handoff"],
  "queries": [
    {
      "text": "Cordant Sagi meeting follow-through",
      "tiers": ["episodic", "vector", "qmd"],
      "scope": { "project": "cordant" },
      "limit": 8
    }
  ],
  "skipReason": null
}
```

Skip decisions are also receipts:

```json
{
  "decision": "search_skipped",
  "timing": "before_tool_use",
  "reasons": ["low_memory_need", "no_stable_entities"],
  "queries": [],
  "skipReason": "Task is a local formatting command with no recall dependency."
}
```

### Scoring

Use a transparent score object per candidate:

- relevance: lexical/semantic match to task and generated query
- recency: time since capture or last access, windowed by task type
- importance: salience tier, pin state, access/reinforcement history
- freshness: source health, source mtime/index time, stale-source penalty
- usefulness: prior successful use in similar tasks or eval traces
- policy: authorization result, redaction state, sensitivity penalty

Recency is a boost, not an override. A recent low-salience memory should lose to an older critical rule when the task depends on that rule.

## Implementation Steps

1. Add `apps/memroos/src/lib/recollection-policy.ts` with trigger, query planning, scoring, thresholding, and receipt types.
2. Add focused tests for required-search, skipped-search, noisy-recency suppression, old-critical promotion, stale-source demotion, and policy-denied candidates.
3. Wire recollection policy into the narrowest runtime seam first: dispatch/context-pack assembly or the agent-runtime memory client.
4. Record receipts through `recordMemoryTrace()` and Phase 117 efficiency events once that event table exists.
5. Add eval cases to `evals/memory-recall/cases.json` for proactive timing and negative recall.
6. Add a small operator-facing read model so NOC can show recent recollection decisions and skipped-search reasons.
