# 125-01 Plan: Multi-Tenant Vaults + Central Tamper-Evident Audit

## Objective

Stop tenancy from collapsing. Per-tenant/per-user vault isolation with team ACL groups, and every knowledge read/write audited centrally (not in user-deletable laptop JSONL) with tenant/user/agent identity, hash-chained, SIEM-exportable. Reuse the PROV hash-chain pattern. `--local` solo mode stays unchanged (Free Solo SKU preserved).

This is a CODE SLICE that builds the operator-side enforcement + the MCP→operator audit bridge. It does NOT stand up a new hosted service or provision real cloud vaults — it makes the existing operator enforce isolation and central audit, with the architectural seams so a hosted deployment plugs in.

## Scope (code)

- Add a `tenant_id` + `user_id` resolution path to the knowledge MCP tools so writes/reads carry real identity.
- Add an operator-side central-audit bridge: knowledge_write/read/delete POST to the operator's audit endpoint (reuse `_post_memroos_agent_api`), writing `audit_entries` with a hash-chain (mirror PROV).
- Per-tenant vault isolation at the `KnowledgeStore` layer: tenant-scoped root paths + ACL group checks; cross-tenant reads fail-closed.
- SIEM-exportable: extend `/api/audit/export` to filter knowledge-audit events by tenant/user/time in one query ("show every artifact user X wrote in Q3").
- `--local` solo mode preserved: when `MEMROOS_OPERATOR_URL` is unset, behavior is exactly today (local JSONL audit, single default-tenant).

## Non-goals / honest stubs (NOT built this phase)

- No new hosted infrastructure or cloud vault provisioning.
- No real OAuth/IdP (ENTOPS-04/05).
- No semantic/LLM content classification of vault contents.
- No retroactive backfill of the old local JSONL into central audit (forward-only; backfill is a documented follow-up).

## Design Contract

### MCP-side identity + central-audit bridge

`store.py`: `write_text`/`read_text`/`delete_file`/`search` accept optional `tenant_id` + `user_id`. When `MEMROOS_APP_URL` + `MEMROOS_AGENT_API_KEY` are set (operator mode), each op POSTs an audit event to `POST /api/audit/knowledge` on the operator (new route) BEFORE returning to the caller — fail-closed: if the audit POST fails, the op fails. Local JSONL still written as a mirror.

`KnowledgeStore` gains a `tenant_root(tenant_id)` resolver: `${root}/tenants/${tenant_id}` when operator mode, else `${root}` (solo unchanged). `_validate_path` enforces the tenant boundary.

### Operator central-audit endpoint

`POST /api/audit/knowledge` (new, operator+ auth via `MEMROOS_AGENT_API_KEY`): writes `audit_entries` row with `event_type=KNOWLEDGE_ACCESS`, entity=tenant/vault, metadata={operation, path, agent_id, user_id, op_hash}, hash-chained per tenant (reuse `checkpointAuditEntryHash` shape). New `AUDIT_EVENT_TYPES.KNOWLEDGE_ACCESS` + `KNOWLEDGE_VAULT` entity type.

### SIEM export extension

`GET /api/audit/export?entityType=KNOWLEDGE_VAULT&userId=X&from=Q3&to=Q3` returns NDJSON — one query. `streamAuditEntries` already supports tenant + entity filters; add `userId` filter on metadata if not present.

1. Two tenants' vaults cannot read each other (regression test, fail-closed).
2. "Show everything user X wrote in Q3" = one query, NDJSON.
