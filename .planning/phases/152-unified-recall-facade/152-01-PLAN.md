# Phase 152 — Unified Recall Facade

**Milestone:** v8.11 Unified Meeting Memory  
**Created:** 2026-07-14  
**Updated:** 2026-07-14  
**Status:** planned  
**Requirements:** URECALL-01, URECALL-02, URECALL-03

## Goal

One MCP tool finds meetings across all enabled QMD collections + knowledge literal + mem0 without requiring collection names.

## Tasks

### T1 — Shared resolver (URECALL-01)

- Add `services/knowledge-mcp/knowledge_system/memory_recall.py`.
- Resolve enabled meeting collections from `~/.memroos/meeting-sources.json` (fallback: known meeting collection names).
- Federate: QMD search per collection + knowledge literal + mem0 `memory_search`.
- Merge/dedupe by path/id; return ranked hits with `lane` metadata.

### T2 — MCP tool (URECALL-02)

- Register `memory_recall(query, limit=10)` as a core tool in `mcp_server.py` + `capabilities.py`.
- Update CORE_TOOLS tests.

### T3 — Orientation (URECALL-03)

- Update `knowledge_system_orientation` to prefer `memory_recall` for “find the meeting” over `qmd -c` / naive `knowledge_search`.

## Success Criteria

1. Resolver returns hits from multiple meeting collections without `-c` in the agent call.
2. `memory_recall` is in CORE_TOOLS.
3. Orientation text mentions the preference.

## Out of Scope

- HTTP multi-search lane (phase 153).
- Provider ingest changes (phase 151).
