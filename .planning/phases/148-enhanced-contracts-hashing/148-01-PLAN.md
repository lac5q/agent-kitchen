# Phase 148 Plan 01 — Enhanced Contracts + Content Hashing/Signing

**Phase:** 148
**Milestone:** v8.6
**Requirements:** SKILLTRUST-01, SKILLTRUST-02
**Status:** potential plan

## Goal

Extend the skill_registry with evidence_examples (SKILLTRUST-01) and content hashing + signing + provenance + trust_level (SKILLTRUST-02). Dispatch can be policy-restricted to signed skills above a trust threshold.

## Tasks

1. Schema migration v10→v11: add `evidence_examples` (TEXT JSON), `content_hash` (TEXT), `signature` (TEXT), `signed_by` (TEXT), `trust_level` (TEXT: 'unsigned'|'signed'|'verified') to `skill_registry` table. Additive, idempotent.
2. Update `skills/registry.ts`: parse `evidence_examples` from SKILL.md frontmatter; compute `content_hash` (SHA-256 of raw_body) on import/publish; store hash in registry.
3. Add signing function: sign the content_hash with `MEMROOS_OPERATOR_API_KEY` (or dedicated `MEMROOS_SKILL_SIGNING_KEY`) using HMAC-SHA256; store `signature` + `signed_by` + `trust_level`.
4. Update `dispatch/skill-lookup.ts`: add optional trust threshold check — if policy requires signed skills, unsigned/incomplete skills are fail-closed denied.
5. Tests: evidence_examples parsing, hash computation, signing/verification, trust threshold dispatch denial, MEMSEC-08 regression.

## Success criteria

1. `evidence_examples` field exists in skill_registry and is parsed from SKILL.md
2. `content_hash` is computed as SHA-256 of raw_body on every import
3. `signature` + `signed_by` + `trust_level` are set when signing key is available
4. Dispatch can be restricted to signed skills above a trust threshold (fail-closed)
5. MEMSEC-08 regression corpus passes byte-identical
