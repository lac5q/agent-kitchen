# 129-01 Plan: Policy Dimensions, Shadow Mode + CI Regression

## Objective

Extend the Phase 128 policy engine with three capabilities:
1. **POLGOV-03**: Dimension-aware rules (subject/object/action/purpose) that can express policies like "GTM agents may read confidential Account claims for purpose=meeting-prep but not export them."
2. **POLGOV-04**: Shadow/dry-run mode that replays a proposed policy version against recent decisions and reports newly-denied/newly-allowed diffs; activation is operator-gated.
3. **POLGOV-05**: A committed decision-case corpus that runs in CI; any policy change producing different outcomes fails unless the diff is explicitly approved.

## Hard constraint (inherited from Phase 128)

The MEMSEC-08 regression corpus MUST still pass byte-identical. Dimension rules are ADDITIVE: they can only TIGHTEN (deny when base allows), never LOOSEN (allow when base denies). Cases that don't supply dimensions are unaffected.

## Design

### POLGOV-03: Policy Dimensions

Extend `manifest.json` rules with optional `dimensions`:
```json
{
  "id": "gtm.meeting-prep-read",
  "domain": "memory-use",
  "description": "GTM agents may read confidential Account claims for meeting-prep but not export",
  "implementation": "memsec.authorizeMemoryUse",
  "dimensions": {
    "subject": { "team": ["GTM"], "role": ["agent"] },
    "object": { "domain": ["client"], "sensitivity": ["privileged", "contract"] },
    "action": ["read", "recall"],
    "purpose": ["meeting-prep", "recall"],
    "effect": "deny"
  }
}
```

- `effect: "deny"` means: if this dimension rule matches the request, the outcome is tightened to deny (even if the base function returned allow). `effect: "allow"` would loosen, but that is FORBIDDEN in this phase (would break byte-identical). Only `effect: "deny"` is supported.
- `matchDimensions(ruleDims, requestDims)` checks each field; arrays are OR-matches, missing fields are wildcards.
- Dimension rules are evaluated AFTER the base wrapped function. If base returns deny, dimension rules can't override. If base returns allow and a deny-rule matches, outcome becomes deny with reason `dimension_deny:<ruleId>`.

### POLGOV-04: Shadow Mode

- `policies/manifest.proposed.json` — a proposed version (same shape as manifest.json).
- `shadowEvaluate(proposedManifest, recentDecisions[])` — replays each decision under the proposed manifest and returns `{ newlyDenied: [], newlyAllowed: [], unchanged: count }`.
- `activatePolicyVersion(proposedManifest)` — operator-gated; validates the proposed manifest, checks it doesn't loosen any base decision, and returns the new active manifest (in production this would be an admin endpoint; here it's a function + test).
- Recent decisions come from `audit_entries` WHERE `event_type = 'policy.decision'` (stored in Phase 128).

### POLGOV-05: CI Regression Corpus

- `policies/corpus.json` — committed decision cases with expected outcomes. Includes MEMSEC-08 cases + new dimension cases.
- `policies/approved-diffs.json` — explicitly approved outcome changes (keyed by case id → new expected outcome + approval note).
- `policy/__tests__/regression.test.ts` — runs the corpus through `evaluatePolicy`, asserts outcomes match expected (or approved-diff), fails on any unapproved difference.
- `check:policy-regression` npm script + CI workflow step.
