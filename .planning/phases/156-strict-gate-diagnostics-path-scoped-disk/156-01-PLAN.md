# Phase 156 — Strict-Gate Diagnostics + Path-Scoped Disk

**Created:** 2026-07-15T20:45:27Z  
**Updated:** 2026-07-15T20:45:27Z  
**Version:** 2026-07-15.1  
**Requirement:** GATE-RESILE-03  
**Milestone:** v8.12 MemRoOS MCP Memory Gate Resilience (Codex)

## Goal

Make strict MCP gate failures diagnosable, and ensure home-directory disk pressure alone does not map to `vector=down` when Qdrant Cloud vector store is connected.

## Scope

- `scripts/memroos-mcp.sh` — enrich `last_error` / `strict_fail` with tier details from health JSON (detail fields), attempt count, and HTTP codes; never print API keys.
- `services/memory/mem0-server.py` — path-scoped `check_disk_space` for Mem0-relevant paths (QUEUE_DB_PATH parent, LOG_DIR); home `df%` alone must not set overall health to force vector tier `down`. Prefer:
  - Keep `vector_store` independent of disk.
  - Disk critical on home-only may warn without flipping `vector_store` or without marking vector tier down in operator mapping.
  - Optionally expose `disk.paths` / scoped results; overall `status` should not treat home-only pressure as vector failure when Qdrant is `connected`.
- `apps/memroos/src/lib/memory/backends.ts` — when mapping mem0 health, do not treat disk-only degradation as vector `down` (degraded OK if product keeps degraded failing strict — but must not become `down`). Prefer surfacing disk in `detail` while status stays `degraded` only if vector_store unhealthy OR runtime unavailable; **home disk alone → do not force vector status down**.
- Tests for disk/vector separation + diagnostic strings.

## Non-goals

- Allowing `degraded` by default in `MEMROOS_ALLOWED_MEMORY_TIER_STATUSES`
- Unsetting `MEMROOS_REQUIRE_SERVER_MEMORY`
