# 133-01 Plan: Shipcheck + Goal/Resume/Standup Commands

## Completion Summary (2026-07-06)

Implemented the first command substrate on top of Phase 132:

- `apps/memroos/src/lib/agent-gsd-control.ts` defines lane proof requirements, durable goal creation/resume, shipcheck verification or bypass receipts, and standup aggregation.
- `POST /api/gsd/goal` creates or resumes a hive delegation, writes a hive action receipt, persists a checkpoint, and returns the Phase 132 packet plus ledger.
- `POST /api/gsd/shipcheck` blocks missing lane proof for research, code, memory, deployment, email/doc, GTM, safety, and ops lanes unless an explicit bypass reason is supplied. Verified or bypassed checks write hive/checkpoint receipts.
- `GET /api/gsd/resume` reconstructs the context packet and run ledger for a goal without relying on chat history.
- `GET /api/gsd/standup` reports active goals, blockers, recent proof, pending approvals, and next actions from durable tables.
- Proxy route-local auth and `scripts/check-route-auth-boundary.mjs` now cover `/api/gsd/*`, so agent API-key auth reaches the handlers in deployed routing.

Verification run:

- `npm run test --workspace apps/memroos -- --run src/lib/__tests__/agent-gsd-control.test.ts src/app/api/gsd/__tests__/route.test.ts src/__tests__/proxy.test.ts`
- `npm run check:route-auth-boundary`
- `npm run typecheck`
- `npm run check:contracts`

## Objective

Give every agent/interface the same durable command substrate:

- `/goal` sets or resumes the task and acceptance contract.
- `/shipcheck` gates completion on lane-specific proof or explicit bypass receipt.
- `/resume` reconstructs working context from MemRoOS state.
- `/standup` summarizes active goals and proof from the ledger.

## Non-Goals

- No UI cards in this slice; routes and library contracts come first.
- No autonomous swarm or council workflow; Phase 134 owns bounded discuss/skill audit.
- No model-routing eval policy; Phase 135 owns lane evals and routing receipts.
- No adapter-specific Discord/Hermes/Telegram behavior; Phase 136 owns thin adapters.

## Acceptance Evidence

- Missing code-lane `focused_tests` proof returns blocked from `/shipcheck`.
- Supplying `focused_tests` verifies and logs a receipt.
- Supplying an explicit bypass reason logs a bypass receipt for missing deployment proof.
- `/resume` returns the Phase 132 packet and ledger for the same goal.
- `/standup` reports the active goal plus the recent shipcheck proof.
