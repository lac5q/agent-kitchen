# 128-01 Plan: Policy Engine Core + Decision Receipts

## Objective

Introduce ONE declarative, versioned policy layer that all existing decision
surfaces evaluate through — MEMSEC retrieval/use gate (`authorizeMemoryUse`),
capability policy (`checkDispatchPolicy` / `checkA2aSendPolicy` /
`checkMemoryWritePolicy`), and `knowledge_policy_check` — while producing a
decision receipt (policy version, rule matched, outcome, reason) that lands in
the audit chain and evidence bundles.

**Hard constraint (success criterion 1):** decisions must be BYTE-IDENTICAL to
today on the MEMSEC-08 regression corpus. Therefore this is **wrap-not-rewrite**:
the engine delegates to the existing, already-tested decision functions as its
"rule implementations" and adds versioning + receipts around them. No decision
outcome changes in this phase.

## Scope (code)

- `apps/memroos/src/lib/policy/engine.ts` — NEW. `evaluatePolicy(request)` that
  routes by `domain` (`memory-use` | `capability` | `knowledge`) to the existing
  decision function, normalizes the result into a `PolicyReceipt`, and stamps the
  active `policyVersion` + `ruleMatched`.
- `apps/memroos/src/lib/policy/policies/` — NEW versioned in-repo policy manifest
  (`manifest.json` with `version`, `rules[]` — each rule = { id, domain, description,
  implementation: "memsec.authorizeMemoryUse" | "capability.dispatch" | ... }).
  Git-tracked; zero paid services; zero external engine dependency.
- `apps/memroos/src/lib/policy/receipt.ts` — NEW. `PolicyReceipt` type +
  `emitPolicyReceipt(db, receipt)` writing an audit row (new
  `AUDIT_EVENT_TYPES.POLICY_DECISION` + `ENTITY_TYPES.POLICY_DECISION`), and a
  helper to attach the receipt to an evidence bundle.
- Migrate call sites to go THROUGH the engine (thin wrappers preserved for
  backward-compatible signatures): `authorizeMemoryUse` callers, `security-policy`
  callers, and the memroos MCP `knowledge_policy_check`.
- `apps/memroos/src/lib/audit/event-types.ts` — add `POLICY_DECISION`
  event + `POLICY_DECISION` entity to the closed enums.

## Non-goals / honest stubs (NOT this phase)

- No new policy DIMENSIONS (subject/object/action/purpose expressiveness beyond

- No shadow/dry-run mode — Phase 129 (POLGOV-04).
- No CI policy-regression corpus gate — Phase 129 (POLGOV-05); this phase only
  proves byte-identical via the existing MEMSEC-08 suite.
- No OPA/Cedar dependency. In-repo declarative manifest only.

## Design Contract

```ts
// engine.ts
export type PolicyDomain = "memory-use" | "capability" | "knowledge";
export interface PolicyRequest {
  domain: PolicyDomain;
  action: string;               // e.g. "recall", "dispatch", "knowledge_write"
  // domain-specific payload passed straight to the wrapped decision fn:
  memoryUse?: { actor; purpose; label };
  capability?: { kind: "dispatch" | "a2a-send" | "memory-write"; ... };
  knowledge?: { toolId; task; metadata };
}
export interface PolicyReceipt {
  policyVersion: string;        // from manifest.json
  domain: PolicyDomain;
  action: string;
  ruleMatched: string;          // rule id from manifest
  outcome: "allow" | "deny" | "redact" | "review-required";
  reason: string;               // safe, no withheld content
  detail?: Record<string, unknown>; // ids/labels only, never payload bodies
  createdAt: string;
}
export function evaluatePolicy(req: PolicyRequest, db?): PolicyReceipt;
```

- The engine calls the SAME underlying function per domain and maps its result
  into the unified `outcome` vocabulary (capability `{allowed:false}` → `deny`).
- `evaluatePolicy` emits a `POLICY_DECISION` receipt (audit row) with version +
  rule + outcome + reason. Reason strings are the existing safe reasons — no
  withheld content is ever included (POLGOV-02).
- Backward-compat: existing exported functions remain and now internally call
  `evaluatePolicy`, so no call-site signature churn and byte-identical outcomes.

**Success criteria (POLGOV-01/02):**
1. MEMSEC-08 regression corpus passes byte-identical (no outcome change).
2. Every decision emits a receipt with policyVersion + ruleMatched + outcome + reason.
3. Receipts contain ids/labels/reasons only — never withheld content.
4. All three decision domains (memory-use, capability, knowledge) evaluate through
   the one engine.

**Escalation:** any decision-outcome change on the MEMSEC-08 corpus; any receipt
that leaks withheld content.
