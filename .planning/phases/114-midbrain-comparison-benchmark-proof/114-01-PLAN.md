# Phase 114 Plan 01 — Midbrain Comparison + Comparative Benchmark Proof

## Goal

Add Midbrain to the MemRoOS competitor system and turn the comparison into a durable benchmark roadmap. The product claim should be precise: Midbrain is strong evidence for retrieval and continual-learning substrate work; MemRoOS is the governed context, dispatch, audit, and proof control plane around memory.

## Requirements

- **COMPETE-01**: Midbrain is represented in marketplace benchmark inputs, generated results, `/vs` comparison pages, sitemap, LLM-readable docs, README, and benchmark methodology notes.
- **COMPETE-02**: Public copy distinguishes MemRoOS's public-evidence architecture score from Midbrain SmartSearch retrieval metrics.
- **SITE-BENCH-01**: The public site has an include-ready benchmark block showing the generated marketplace ranking, Midbrain's `65.21` score, and a clear caveat that SmartSearch retrieval metrics are third-party paper results until rerun.
- **BENCH-01**: Comparative benchmark plan defines three lanes: public-evidence architecture scoring, external retrieval-task scoring, and MemRoOS operational workflow scoring.
- **BENCH-02**: External retrieval lane specifies LoCoMo / LongMemEval-style datasets or adapters, answer normalization, precision@k, recall@k, MRR, false-positive rate, p95 latency, token spend, and caveat reporting.
- **BENCH-03**: Comparative retrieval harness has a concrete implementation path for LoCoMo, LongMemEval, and LongMemEval-V2-style tasks, including fixture ingestion, adapter contracts, scorer normalization, and report rendering.
- **RETRIEVAL-01**: SmartSearch-inspired retrieval backlog covers deterministic entity extraction, entity expansion, tier fan-out, reranking, dedupe, score-adaptive context packing, and temporal caveat handling.
- **RECEIPTS-01**: Retrieval receipts become public-facing product proof: retrieved, injected, ignored, score, tier, source, authorization result, and why the memory entered or missed the context pack.
- **SEO-PROOF-01**: Public proof metrics render meaningful fallback text for crawlers and LLM fetchers without waiting for client-side counter animation.

## Comparative Benchmark Plan

### Lane 1 — Public-Evidence Architecture Benchmark

Keep the current marketplace benchmark as the broad product-comparison lane. It scores public evidence for governance, typed memory, orchestration, deployment control, performance path, observability, and portability. Use it to answer "which platform looks production-ready from public evidence?"

Deliverables:

- `evals/marketplace-agentic-memory/providers.json`
- `evals/marketplace-agentic-memory/results/latest.json`
- README/docs/blog summaries with caveats
- `/vs/<competitor>` pages
- a site-facing benchmark block that renders the generated top ranking and explicitly labels third-party paper metrics

### Lane 2 — External Retrieval Task Benchmark

Add a separate benchmark lane for retrieval quality so MemRoOS can be compared against research systems without conflating metrics.

Dataset candidates:

- LoCoMo-style long conversation memory tasks
- LongMemEval-style long-context memory tasks
- LongMemEval-V2-style agent environment experience tasks
- A small MemRoOS-public synthetic set that mirrors product, sales, engineering, and AI-ops workflows

Metrics:

- `precision@k`
- `recall@k`
- `MRR`
- `false_positive_rate`
- `p95_latency_ms`
- `token_spend`
- `context_pack_bytes`
- `answer_supported_by_retrieved_source`

Implementation sequence:

1. Add `evals/comparative-retrieval/` with fixture schema, adapter contract, and normalization rules.
2. Add dataset loaders:
   - `locomo-loader.mjs` for long multi-session conversations, QA, event summaries, and optional multimodal fields.
   - `longmemeval-loader.mjs` for user/assistant history sessions and question categories.
   - `longmemeval-v2-loader.mjs` for web-agent environment memory questions once the V2 data/code package is available.
3. Implement a MemRoOS adapter that runs entity extraction, tier fan-out, rerank, dedupe, authorization filtering, and context packing.
4. Add baselines: lexical/FTS-only, vector-only, full-context where legally/runtimely usable, and no-memory answerer.
5. Normalize answers with exact match plus judge-assisted semantic equivalence for non-extractive answers; require source support when a retrieved memory is used.
6. Report Midbrain SmartSearch numbers as cited external paper results until direct runnable access exists; label them as non-rerun third-party results.
7. Render results separately from the marketplace architecture benchmark.

## What It Takes To Run LoCoMo / LongMemEval Style Benchmarks

### Build Effort

- **Data licensing and acquisition**: pull official datasets/code, record license and citation requirements, and avoid committing restricted raw data if redistribution is not allowed.
- **Fixture conversion**: convert conversations/sessions/questions into a stable MemRoOS fixture shape: `corpus`, `sessions`, `question`, `expected_answer`, `evidence_spans`, `task_type`, `temporal_metadata`.
- **Memory ingestion**: seed the same corpus through MemRoOS memory paths, not a shortcut index, so the benchmark measures the actual retain/retrieve path.
- **Adapter contract**: expose `ingest`, `retrieve`, `answer`, and `receipt` methods so MemRoOS, lexical, vector-only, and future competitor adapters can run through the same harness.
- **Scoring**: implement `precision@k`, `recall@k`, `MRR`, answer correctness, abstention correctness, false-positive rate, p95 latency, token spend, and source-support coverage.
- **Receipts**: store retrieved/injected/ignored memories per question so benchmark failures are debuggable and site claims can link to evidence.
- **Report generation**: write JSON and Markdown summaries; optionally render a small public chart block for the site.

### Expected Size

- **Small proof spike**: 2-3 days. Run a 20-50 question subset, prove harness shape, publish caveated internal numbers only.
- **Credible public benchmark**: 1-2 weeks. Full fixture loader, reproducible runner, baselines, receipts, report generation, and documentation.
- **Serious comparative benchmark**: 2-4 weeks. Add LongMemEval-V2 style agent-environment tasks, cost controls, multiple model readers, deterministic reruns, and public evidence bundles.

### First Implementation Cut

1. Create `evals/comparative-retrieval/fixtures/README.md` with dataset sourcing instructions and non-redistribution rules.
2. Create `evals/comparative-retrieval/schema.json` for normalized memory tasks.
3. Create `scripts/run-comparative-retrieval-evals.mjs`.
4. Implement the MemRoOS adapter using existing recall/context-pack code paths.
5. Run a 25-question smoke set before attempting full LoCoMo or LongMemEval.

### Lane 3 — Operational Workflow Benchmark

This is MemRoOS's home-field benchmark and should not be hidden behind retrieval metrics. It measures whether a team can resume work across agents with proof.

Workflow cases:

- Product discovery to PRD
- Sales call to account brief/follow-up
- Engineering incident to debug handoff
- AI-ops dispatch with approval and rollback

Metrics:

- context pack completeness
- provenance coverage
- operator approval points captured
- dispatch receipt present
- memory-save receipt present
- replay or rollback handle present
- residual risk surfaced
- human re-ask reduction

## Highest-Benefit Roadmap Additions

1. **Retrieval receipts in every run**: highest buyer-facing benefit because it turns "memory worked" into inspectable proof.
2. **SmartSearch-inspired retrieval lane**: highest technical credibility benefit because it closes the retrieval-quality gap exposed by Midbrain.
3. **External retrieval benchmark harness**: highest market credibility benefit because it lets MemRoOS say where it wins and where it is still improving without mixing benchmark types.
4. **Temporal caveat handling**: high user benefit because Midbrain and Zep both expose temporal memory as a key battleground.
5. **Crawler-safe proof surfaces**: fast SEO/LLM benefit because public evidence must survive static fetches.
