# 127-01 Plan: Write-Side Native-Memory Enforcement + Exit Tool

## Objective

(1) ENTOPS-08 (CODE): a `memroos export --flat` CLI producing a markdown tarball of the org vault with a signed manifest, plus per-user DSAR export (vault + audit trail) in one action, and right-to-delete tombstoning within the compliance window (executes via MEMLIFE erasure semantics — here a tombstone marker, full MEMLIFE pipeline is a later milestone). (2) ENTOPS-07 (HONEST STUB): the native-memory-interception half (Claude auto-memory, Hermes `memory add`, Codex `/memory` routing to MemroOS first, replay under budget) requires changing each harness's memory write path and a running Hermes to regression-test. We ship the operator-side sink/filter/budget-replay library + the `directive_diff` alert hook, and explicitly stub the per-harness interception as a documented handoff.

## Scope (code)

- ENTOPS-08: `bin/memroos.mjs` CLI with `export --flat` (org vault tarball + signed manifest) and `export --dsar --user X` (per-user vault + audit). Right-to-delete tombstones via a new `erasure_tombstones` table + MEMLIFE-shaped API (non-destructive tombstone, never breaks audit chain).
- ENTOPS-07 (code slice): operator-side `lib/native-memory/sink.ts` — a `POST /api/native-memory/ingest` endpoint that receives harness auto-memory writes, runs them through the directive budget + filter, and returns the sanitized replay payload. `directive_diff` alert (never deletes). The per-harness wiring (Claude/Hermes/Codex) is the HONEST STUB.

## Non-goals / honest stubs

- No modification of Claude Code / Hermes / Codex internal memory write paths this phase (each needs its runtime + integration test; documented in handoff).
- Hermes MEMORY.md skills-routing layer is NOT touched (ENTOPS-07 preserves it).
- Full MEMLIFE derivative-chasing erasure (vector/graph/FTS/qmd purge) is a later milestone; here we tombstone + flag for MEMLIFE.

## Existing surfaces (verified)

- `apps/memroos/src/app/api/audit/export/route.ts` + `streamAuditEntries` — DSAR audit export basis.
- `apps/memroos/src/lib/audit/knowledge-chain.ts` (Phase 125) — central audit for vault contents.
- No `bin/`, no `memroos` CLI (Phase 126 establishes scripts/memroos.mjs pattern).
- `apps/memroos/src/lib/directive-budget.ts` (Phase 126) — `directive_diff` to reuse.
- No `erasure_tombstones` table today.

## Design Contract

### ENTOPS-08 export CLI

`bin/memroos.mjs` (NEW, added to root package.json `bin`): argv parser (`export` subcommand). `export --flat [--tenant T]`: tarballs `${vault_root}/tenants/<T>` markdown + a signed manifest (sha256 tree hash + gitSha + timestamp). `export --dsar --user U [--tenant T]`: vault files authored by U (from central audit) + their audit trail (NDJSON), one zip. `delete --user U`: inserts `erasure_tombstones` rows (entity_type, entity_id, tenant_id, reason='dsar', tombstoned_by, tombstoned_at, scheduled_purge_at); NEVER deletes audit rows; the tombstone is the compliance-window marker. Routes: `POST /api/dsar/export` + `POST /api/dsar/delete` (admin) wrapping the same logic for UI access.

`erasure_tombstones` table (migration v4 additive): `id, tenant_id, entity_type, entity_id, reason, tombstoned_by, tombstoned_at, scheduled_purge_at, purged_at`.

### ENTOPS-07 operator sink (code slice)

`POST /api/native-memory/ingest` (operator+API-key): body `{source: 'claude'|'hermes'|'codex', agentId, userId, content, memoryPath}`. Pipeline: `directive_diff` (alert, never delete) → `filterNativeMemory(content)` (redact secrets via existing scanner) → `computeDirectiveBudget` (warn) → returns `{replay: sanitizedContent, budgetStatus, diff}`. The caller (a future harness hook) writes `replay` to the local file. No harness is modified this phase — the sink + contract is the deliverable.
