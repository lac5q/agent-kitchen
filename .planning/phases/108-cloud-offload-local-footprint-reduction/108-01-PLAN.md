# Phase 108 Plan 01 - Cloud Offload + Local Footprint Reduction

## Goal

Reduce the load MemRoOS places on Luis's local machine by moving eligible permanent storage, heavy indexes, and background work to cloud or managed services while keeping local state bounded, recoverable, and privacy-safe.

## Scope

- Inventory every local persistence path: `data/conversations.db`, SQLite WAL/SHM files, `services/memory/logs`, `~/.cache/qmd`, `~/.mem0`, `~/.memroos/vault`, `~/github/knowledge`, local state-store files, LaunchAgent logs, and orchestration checkpoint files when present.
- Classify each path as permanent source of truth, rebuildable cache, replay queue, raw evidence, runtime secret/config, or disposable log.
- Choose managed/cloud targets for each eligible store: managed Postgres or equivalent for operational SQLite tables, remote qmd/search workers or managed indexes for knowledge search, object storage for raw vault artifacts, managed graph for Neo4j, cloud-backed memory/vector services, and centralized log/queue retention.
- Treat compressed local vector indexes such as Turbovec as future-only shadow-index experiments, not canonical memory backends. Qdrant remains the canonical vector store unless a later approved phase changes the memory backend contract.
- Define migration and sync flows with restore, rollback, hash verification, privacy labels, encryption key handling, and degraded/offline behavior.
- Add local cache caps and prune workflows so local disk and memory usage cannot grow without visible operator warnings.
- Surface footprint and sync status in NOC/setup: local size by store, cache pressure, last sync, remote health, prune backlog, rollback readiness, and remaining local-only data.

## Verification Plan

- Run an inventory command that reports local store sizes, classifications, source-of-truth, and prune safety.
- Prove remote degraded states are visible and do not silently drop memory writes, audit rows, vault artifacts, or search freshness.
- Prove local prune commands remove only rebuildable caches/logs or already-offloaded artifacts.
- Prove restore can rebuild local hot caches from cloud-backed state.
- For any future Turbovec or compressed-vector test, require Luis approval before implementation, then compare against the current vector baseline with recall@5, precision@5, MRR, false-positive rate, and p95 latency gates.
- Run focused tests for migration metadata, retention policy, vault hash verification, and no-secret/no-raw-token leakage.
- Run `git diff --check`.

## Exit Criteria

Phase 108 can close only after MemRoOS has a documented and verified cloud/offload operating profile that materially reduces local disk/RAM pressure, preserves privacy and rollback guarantees, makes all remaining local permanent state explicit, and keeps unapproved vector-backend experiments out of the implementation path.
