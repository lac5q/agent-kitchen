<evidence_contract>
1. Create `reports/operator-load/runtime-bottleneck/suite-manifest.json`. It uses `schemaVersion: "1"` and records `suiteManifestHash`, `fixtureHash`, `operatorWorkloadHash`, `retrievalWorkloadHash`, both configuration hashes, Git revision, host CPU and memory, runtime versions, target URL, dependency health, and degraded mode. Do not store credentials or private source records.
2. Preserve operator runs as `run-01.json` and `run-02.json`. Each accepted run must last at least 300 seconds, record at least 500 requests, and measure `maxInFlight >= 5`. Each report records `durationMs`, `totalRequests`, `errors`, `errorRate`, `p50Ms`, `p95Ms`, `p99Ms`, `throughputRps`, `configuredAgents`, and `maxInFlight` with JSON numeric types and millisecond or requests-per-second units.
3. Use the current operator SLO: `p95Ms < 500` and `errorRate < 0.001`. A zero-request, placeholder, stale, metadata-incomplete, or degraded report is invalid evidence.
4. Preserve retrieval runs as `evals/comparative-retrieval/results/runtime-bottleneck/run-01.json` and `run-02.json`. Both use the suite fixture hash, retrieval workload hash, retrieval configuration hash, seed, and task count. Each report records precision@K, recall@K, MRR, false-positive rate, answer support, `p50LatencyMs`, `p95LatencyMs`, completed and failed task counts, and token accounting.
5. Preserve raw artifacts as `reports/operator-load/runtime-bottleneck/profiles/run-N.cpu.json`, `run-N.heap.json`, and `traces/run-N.json`. Preserve measured attribution as `attribution/run-N.json`. The decision must link each file.
6. `schemas/runtime-bottleneck-evidence.schema.json` defines exact names, types, units, required fields, and `schemaVersion: "1"`. Token and dependency fields use `{ status, value, reason }`. `status: "measured"` requires a finite numeric value and a null reason. `status: "unavailable"` requires `value: null` and a non-empty reason. Zero is valid only when the status is measured.
7. Record Qdrant, Neo4j, Ollama, LLM, SQLite/queue, application CPU/heap, and unknown time. For each profiled request class, component time plus unknown time must reconcile to end-to-end time within the larger of 5 ms or 10 percent.
8. Accepted runs in each lane must match that lane's workload and configuration hashes. Operator and retrieval workload hashes are intentionally different. Both lanes must match the common `suiteManifestHash` and `fixtureHash`.
</evidence_contract>

<steps>
1. Extend the operator runner to emit all operator evidence fields. Measure peak in-flight requests instead of treating configured agent count as concurrency.
2. Extend the retrieval aggregate with p50 latency. Preserve existing p95 behavior. Export token and dependency evidence with explicit availability state.
3. Add the JSON schemas and machine-readable evidence checker. It must reject missing fields, zero requests, low sample counts, short runs, hash drift, missing raw artifacts, unreconciled attribution, and fewer than two accepted runs.
4. Capture two operator runs and two retrieval runs with the declared fixture manifest. Keep raw observations and generated summaries in the canonical report paths.
5. Profile representative slow requests. Attribute only observed time. Label the remainder `unknown`.
6. Write matching JSON and Markdown decision records. Select `keep`, `optimize-current-stack`, or `bounded-shadow-extraction`.
</steps>

<decision_gate>
`schemas/runtime-bottleneck-decision.schema.json` defines `schemaVersion`, `decision`, evidence links, thresholds, and required extraction fields. `scripts/check-runtime-bottleneck-evidence.mjs` selects exactly one result in this order:
1. Select `bounded-shadow-extraction` only when at least two accepted operator runs miss the p95 SLO, one named local CPU, heap, SQLite, queue, or indexing component accounts for at least 60 percent of p95 latency in every failed run, and remote plus unknown time is below 40 percent in every failed run. The decision must also name one bounded interface, one shadow-only boundary, rollback criteria, and comparison metrics.
2. Otherwise select `optimize-current-stack` when at least two accepted operator runs miss either accepted SLO condition: `p95Ms >= 500` or `errorRate >= 0.001`. The decision must name the measured limiting component and a current-stack change.
3. Otherwise select `keep`.

The checker rejects a decision that does not match this order. This phase does not authorize a production cutover or a wholesale rewrite.
</decision_gate>
