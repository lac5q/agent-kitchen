# 115-04 Plan: Runtime Topology Manifest Enforcement

## Objective

Complete `ARCHREV-04` by making the shared runtime topology manifest the enforceable source for service names, ports, health checks, dependencies, and supervision-mode wiring across Docker compose, `start.sh`, and launchd startup.

## Scope

- Add Docker compose service names to `apps/memroos/src/lib/runtime-topology.json`.
- Add manifest-owned Docker port environment variables for mem0 and orchestration.
- Add manifest-owned Docker service dependencies for the MemRoOS app.
- Align the Docker app healthcheck with the manifest path `/api/health`.
- Strengthen `scripts/check-runtime-topology.mjs` so it validates Docker service names, `depends_on`, env-backed port mappings, Docker health URLs, manual-script topology lookups, and launchd topology lookups.
- Add focused `node:test` regression coverage for Docker health-path drift and expanded artifact validation.

## Non-Goals

- No Docker image or deployment behavior rewrite.
- No service startup order change beyond validating the existing `depends_on` contract.
- No public deployment action.

## Verification

- `node --test scripts/check-runtime-topology.test.mjs`
- `npm run check:runtime-topology`
- `git diff --check apps/memroos/src/lib/runtime-topology.json docker-compose.yml scripts/check-runtime-topology.mjs scripts/check-runtime-topology.test.mjs`

## Done Criteria

1. Manifest names Docker service mappings and dependencies for Docker-supervised services.
2. Docker compose app healthcheck uses the manifest health path.
3. Runtime topology checker fails on Docker health-path drift.
4. Runtime topology checker reports concrete validated contracts for Docker, manual script, and launchd artifacts.
