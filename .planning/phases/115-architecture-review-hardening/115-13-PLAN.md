# 115-13 Next Trust-Boundary Upgrade Gate

Status: completed 2026-06-27

## Objective

Close `ARCHREV-09` by requiring explicit proxy/auth regression coverage and a migration checklist before Next.js framework upgrades or direct `proxy.ts` edits can change the request trust boundary.

## Scope

- Add `docs/next-trust-boundary-upgrade.md` with the reviewed Next dependency, reviewed `proxy.ts` hash, migration checklist, and required verification command.
- Add `scripts/check-next-trust-boundary.mjs` and a Node test for the checker.
- Validate that `apps/memroos/src/proxy.ts` remains the named proxy export, owns matcher config, does not configure runtime, and has no competing `src/middleware.ts`.
- Require regression coverage for matcher inclusion/exclusion, expired or malformed JWT credentials, reviewer role escalation, route-local auth path traversal, and Bearer token precedence over `access_token` cookies.
- Add `npm run check:next-trust-boundary` and run it in CI after lint.

## Verification

- `node --test scripts/check-next-trust-boundary.test.mjs`
- `npm run check:next-trust-boundary`
- `npm run typecheck --workspace apps/memroos`
- `npm run lint --workspace apps/memroos`
- `git diff --check`

## Notes

- The installed Next package does not include `node_modules/next/dist/docs`; the checklist records that agents must consult current official Next proxy documentation when local docs are absent.
- Next 16.2.7 still exports the test matcher helper under the middleware-era name, so the test uses the installed helper while preserving the proxy-name marker for upgrade review.
