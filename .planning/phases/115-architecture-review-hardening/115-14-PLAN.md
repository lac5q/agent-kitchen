# 115-14 Route Auth Boundary Gate

Status: completed 2026-06-27

## Objective

Close `ARCHREV-01` by proving privileged API groups have handler-local operator or agent authorization and by adding a drift gate so `proxy.ts` is not the only security boundary.

## Scope

- Add `scripts/check-route-auth-boundary.mjs` and checker unit tests.
- Validate every `ROUTE_LOCAL_AUTH_API_ROUTES` proxy bypass pattern has explicit coverage in the checker.
- Validate each covered handler contains a local auth primitive such as `authorizeRegistryWrite`, `authenticateAgentHeaders`, `authorizeChatGptAction`, or session/role checks.
- Include the proxy operator/admin routes so proxy-enforced routes also retain in-handler defense in depth.
- Require the focused regression tests for operator-auth, agent-context auth, checkpoint/version/memory-trace/observability/hive/model-routing non-local denial.
- Add `npm run check:route-auth-boundary` and run it in CI after lint.

## Verification

- `node scripts/check-route-auth-boundary.mjs`
- `node --test scripts/check-route-auth-boundary.test.mjs`
- `npm run check:route-auth-boundary`

## Notes

- The marketing-app split remains a deployment decision, not a blocker for handler-local route auth. Current completion means the shared app has defense-in-depth for privileged route groups and a CI gate against proxy bypass drift.
