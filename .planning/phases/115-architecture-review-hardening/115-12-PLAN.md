# 115-12 Recall Canary CI and Scheduled Gate

Status: completed 2026-06-27

## Objective

Close `ARCHREV-07` by making memory recall regression coverage run in CI or on a schedule using the existing committed recall cases and thresholds.

## Scope

- Add `npm run check:recall-canary` at the monorepo root.
- Add `apps/memroos/src/lib/__tests__/memory-recall-canary-ci.test.ts`.
- Execute the committed gold recall cases from `evals/memory-recall/cases.json` through `runMemoryRecallEvalSuite({ mode: "gold" })` against a temp SQLite DB.
- Fail on the existing recall, precision, MRR, latency, tier coverage, timing, and avoided-fact thresholds already enforced by `memory-recall-evals.ts`.
- Add `workflow_dispatch`, a daily `schedule`, and a dedicated `recall-canary` job in `.github/workflows/ci.yml`.

## Verification

- `npm run check:recall-canary`
- `git diff --check`

## Notes

- The deterministic CI canary uses the gold layer because those fixtures are episodic and do not require mem0/Qdrant or operator secrets.
- Live vector canary remains available through `npm --prefix apps/memroos run eval:memory -- --canary` in environments with the app, operator key, and mem0 running.
