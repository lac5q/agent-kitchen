# 115-05 Plan: Typed Env Startup Validation

## Objective

Complete `ARCHREV-05` by validating MemRoOS app configuration through one typed env module at startup and reconciling root config files with their current canonical roles.

## Scope

- Expand `apps/memroos/src/lib/env.ts` from path-only validation to typed app configuration for core ports, URLs, memory paths, A2A settings, root config paths, embedding settings, and external datastore credential shapes.
- Add `validateMemroosEnvAtStartup()` and call it from Next instrumentation before schedulers start.
- Move server constants, A2A config, knowledge collection config paths, context-source config paths, and embedding provider config onto `loadMemroosEnv()`.
- Split browser-only display constants into `apps/memroos/src/lib/ui-constants.ts` so client components do not evaluate server env validation.
- Reconcile root config status in `env.ts`: `agents.config.json` is legacy compatibility state, while `collections.config.json` and `context-sources.config.json` remain active root config files with typed override envs.

## Non-Goals

- No secret requirement change for local development.
- No deletion or movement of `agents.config.json` in this run.
- No full migration of every route-specific feature toggle, adapter credential, subprocess env spread, or test env mutation. Those remain explicit runtime/config follow-up surface and are not claimed as eliminated.

## Done Criteria

1. Malformed typed app env values fail closed through `loadMemroosEnv()` and startup validation.
2. A2A, root config paths, server constants, and embedding provider settings read through the typed env module.
3. Client components import browser-safe UI constants instead of the server config constants module.
4. Root config status identifies `agents.config.json` as legacy and active root config files as typed env-owned.
