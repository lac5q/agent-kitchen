# Phase 155 — Mem0 Hang Immunity

**Created:** 2026-07-15T20:45:27Z  
**Updated:** 2026-07-15T20:45:27Z  
**Version:** 2026-07-15.1  
**Requirement:** GATE-RESILE-02  
**Milestone:** v8.12 MemRoOS MCP Memory Gate Resilience (Codex)

## Goal

Stop Mem0 from hanging itself via self-HTTP `/health` loops; keep Qdrant probe caching; add lightweight `/livez`; let `healthcheck.sh` auto-restart hung Mem0 with cooldown.

## Scope

- `services/memory/mem0-server.py`
  - Refactor `_qdrant_health_checker` to call in-process health/Qdrant check + reset helpers instead of `httpx` to `http://localhost:3201/health` and `/memory/reset`.
  - Ensure `/health` Qdrant check uses cached probe interval (reuse `_qdrant_probe_*` or dedicated health cache).
  - Add `GET /livez` — process liveness only (no Qdrant/disk).
- `services/memory/healthcheck.sh`
  - Detect hung Mem0 (empty/timeout health) and restart via launchctl/script with cooldown state file.
- Tests in `services/memory/tests/` for livez + no self-HTTP in checker (or checker uses in-process path).

## Non-goals

- Changing operator TS probe timeout (Phase 154)
- Disk path scoping (Phase 156)
- Unsetting strict memory

## Verification

```bash
cd services/memory && python -m pytest tests/ -q -k "health or livez or qdrant" 
# or targeted new tests
```

## Constraints

- No secrets in logs
- Cooldown must prevent restart storms
- Worker must not commit
