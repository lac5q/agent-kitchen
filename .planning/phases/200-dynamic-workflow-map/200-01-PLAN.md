# Phase 200: Dynamic Workflow Map (FLOWMAP-01..05)

**Phase ID:** 200
**Milestone:** v8.28 Connected Tools as Memory
**Date added:** 2026-07-27
**Status:** IN PROGRESS (FLOWMAP-01..04 landed; 05 open)
**Depends on:** none (UI + seed path only; does not touch the memory boundary)

## Goal

The `/flow` workflow map was a hardcoded literal. It rendered five fixed agent
names — Sophia, Maria, Alba, Gwen, Cto — at hand-typed pixel coordinates, on
every host, regardless of what was actually registered. On cordant-hermes-01
that meant the operator was looking at a confident diagram of agents that do
not exist there.

## What was actually wrong — two bugs, not one

**1. The map never read live state.** `topology-canvas.tsx` held `NODES`,
`EDGES`, and `PULSE_EDGES` as module-level constants. Even the "16 nodes · 22
active edges" caption was `Object.keys(NODES).length` — presentation dressed as
telemetry. `node-detail-rail.tsx` was a second copy of the same literal, so
clicking a node produced an equally wrong description.

The literal had already drifted: `alba` sat at y=200 and `gwen` at y=320, a
120px gap where a node had been deleted by hand.

**2. cordant-hermes-01 has zero registered agents.** Verified against the live
DB: every one of the 14 `agent_*` tables holds 0 rows, while oracle-1 holds 59.
So a *correctly* dynamic map would have rendered an empty column — which is why
the hardcoded literal had been masking a real gap rather than merely being
stale.

Root cause: `seedRegisteredAgents()` reads `agents.config.json` through
`findConfigFile()`, and **`agents.config.json` was never copied into the Docker
image**. The seed hit its `catch` and returned silently. `NODE_ENV=production`
in the container, so seeding was enabled — it simply had no file to read.

## Sub-IDs (acceptance criteria)

### FLOWMAP-01 — Topology assembled from live state ✅ DONE

`lib/workflow/topology.ts` + `api/flow/topology/route.ts`. Assembled
server-side: the server already has DB access and the session cookie already
authenticates it, where a client would need three round trips and cannot read
tables directly.

What is derived vs declared, deliberately:

| Column | Source |
|---|---|
| AGENTS | `registered_agents` |
| STORES | live row counts from the tables they represent |
| SOURCES | connected Nango providers |
| Gateway · MemroOS · Outcomes | **declared** — structural, exactly one of each |

Declaring the spine is correct, not a shortcut: deriving a constant would mean
inventing a lookup for something that exists whether or not anything is
connected.

### FLOWMAP-02 — Layout computed, not stored ✅ DONE

Columns keep their hand-tuned x positions (that is design worth preserving);
y is distributed evenly from the column's actual node count. Tested at 1, 3,
12, and 59 agents: no two share a y and none escape the canvas. The old literal
could not survive a registry of 59.

### FLOWMAP-03 — No invented telemetry ✅ DONE

The old edges carried weights like `["memory","sophia",0.5,"pack"]` — a
hand-typed number rendered as line thickness, indistinguishable from a
measurement. Edges now carry `measured: boolean`. Weight scales with real
activity counts when supplied; otherwise it is a flat `UNIFORM_WEIGHT` and
`measured` is false. **Pulse animations run only on measured edges.**

Store subtitles distinguish "table exists and is empty" from "table absent"
(`unavailable`) — a confident "0 documents" for a table that does not exist is
the same class of lie.

### FLOWMAP-04 — Empty state is load-bearing ✅ DONE

An empty column renders a notice explaining why, not a blank grid. On
cordant-hermes-01 today that reads: *"No agents registered on this host — the
registry is empty, so the AGENTS column has nothing to draw."* Silence would
look more broken than wrong names.

### FLOWMAP-05 — Seed reaches the container ⬜ OPEN (deploy pending)

`docker/Dockerfile.memroos` now copies `agents.config.json` into both the
builder and runner stages. **Requires a rebuild on both hosts to take effect**
— the file is baked at image build time, so a restart alone changes nothing.

Note: `agents.config.json` holds 20 agents while oracle-1's registry holds 59,
so most of oracle-1's agents arrived by runtime registration rather than seed.
The seed is a floor, not the whole roster.

## Constraints

- UI and seed path only — does not touch the memory security boundary.
- No hardcoded agent names anywhere in the render path.
- Missing config still degrades gracefully; the copy makes seeding *possible*,
  not *required*.
