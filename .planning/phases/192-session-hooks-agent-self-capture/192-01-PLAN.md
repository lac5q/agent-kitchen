# 192-01 Plan: Session Hooks + Agent Self-Capture

**Milestone:** v8.30 Seamless Memory Adoption
**Created:** 2026-07-26
**Depends on:** Phase 191 (probe to call at session start), Phase 96 (`captureCodingAgentSession`), Phases 167-171 (v8.16 observe plane)
**Design:** `.planning/design/memory-adoption-v1.md`

## Progress

- Not started.

## Objective

Make the first recall of a session happen *for* the agent, and make the end of a session produce a structured memory without anyone remembering to ask. This is the "first call is free" half of the adoption loop, and the backstop that catches harnesses which cannot run hooks.

## Baseline (audited 2026-07-26)

- **The repo ships no hooks at all.** No `.claude/` settings, no `SessionStart` / `PreToolUse` / `UserPromptSubmit` / `Stop` config anywhere. `.githooks/` holds only `pre-commit`.
- `scripts/claude-goal-state-handoff-hook.sh` is the only hook-shaped script — it reads hook JSON on stdin and publishes `GOAL_STATE.md` over the agent-context bus. It is a handoff publisher, not memory capture, and **nothing installs it into a hook config**.
- `GSD_PORTABLE_HOOKS=1 npx get-shit-done-cc@... --portable-hooks` in `scripts/setup-codex-cloud.sh:157` and `setup-cursor-cloud.sh:141` installs hooks from an **external npm package**, not from this repo.
- `scripts/install-agent-integrations.sh` already fans `AGENTS.md` + skills + MCP config out to 13+ targets (`TARGETS` at `:136-159`, idempotent, cron-refreshable) — but installs **no hooks**.
- Capture exists and is well-governed: `POST /api/agent-memory/capture` (26 lines) → `captureCodingAgentSession()` (`lib/agent-memory-continuity.ts:205`) writes `agent_session_captures` plus `INSERT OR IGNORE INTO agent_memory_candidates` (`:401`), with content-scanner redaction, `captureHash` dedup, and vault sealing. Depth policy in `lib/observe-capture-depth.ts` (default `relevant`), documented at `docs/integrations/observe-capture.md`. 11 runtimes in `CodingAgentRuntime` (`:15-27`).
- **But agents cannot reach it:** the route uses `authorizeRegistryWrite` — operator key only.
- **And its only feeder is nearly empty:** `scripts/run-observe-sidecar.mjs` (177 lines) walks 7 session roots, but `summarize()` (`:73-88`) sets `summary = first 5 lines of the JSONL, truncated to 240 chars`. Decisions, files, commands, errors, and verification — all fields `captureCodingAgentSession` accepts — are left empty.
- **And nothing schedules it.** `npm run observe:sidecar` exists; no cron, launchd plist, or systemd unit registers it. `scripts/com.memroos.batch-embed.plist` is unrelated.
- Maturity matrix lives at `lib/observe-sidecar.ts:49-128` (`jsonl` / `hooks+jsonl` / `mcp-partial` / `plugin` / `limited`) with drift gate `scripts/check-observe-maturity-drift.mjs`.

## Scope

- Agent-key auth on the capture route, scoped to the agent's own sessions.
- Two repo-owned hooks (session-start brief, session-end capture-gate) installed by the existing installer.
- A committed, drift-gated hook capability matrix per harness.
- Structured extraction v2 in the sidecar.
- A real schedule for the sidecar plus heartbeat visibility.

## Non-Goals

- No blocking hooks. A hook failure or timeout never prevents the session from proceeding.
- No transcript dumping into mem0; depth policy and vault sealing stay exactly as they are.
- No raising the default depth above `relevant`.
- No dependence on the external GSD portable-hooks package for MemRoOS-owned hooks.
- No claim of full fidelity for closed IDEs without vendor hooks.
- No new capture schema — reuse Phase 96 (`OBSERVE-09` already locks this).

## Design Contract

### D1 — Capture auth scoping (SELFCAP-01)

Accept `authenticateAgentHeaders` in addition to the operator key. An agent-authenticated capture may only write with `agent_id` equal to the calling key's agent, and only for runtimes that key is registered for. Operator key retains today's unrestricted behavior for the sidecar. Rate-limit per agent key. Depth policy is enforced server-side regardless of caller, so a compromised or over-eager agent cannot request `full` where policy forbids it.

### D2 — Hook contract (SELFCAP-02)

| Hook | Event | Action | Budget | On failure |
|---|---|---|---|---|
| `memroos-memory-brief` | session start | `POST /api/memory/prior-work` with repo, branch, cwd, and any goal ref; inject digest | ≤600 tokens, ≤2s | proceed; write miss receipt |
| `memroos-capture-gate` | stop / pre-compact | `POST /api/agent-memory/capture` with structured session content, or a typed skip receipt | ≤5s | proceed; receipt + NOC Attention item |

Both hooks read config from the same env the MCP registration uses (`MEMROOS_AGENT_API_KEY`, base URL). Both are idempotent — re-firing on the same session is deduped by `captureHash`. Neither ever writes to stdout in a way that corrupts the harness's hook protocol; all diagnostics go to a log path.

### D3 — Capability matrix (SELFCAP-03)

Extend the existing observe maturity matrix rather than creating a second one. Per harness record: hook support (`native` / `portable` / `plugin` / `none`), which of the two hooks are installed, and the fallback in use when hooks are unavailable (skill + sidecar). Gate drift with `scripts/check-observe-maturity-drift.mjs` so the table cannot silently overstate coverage. Harnesses with `none` are documented as sidecar-only — no false full-capture claim (mirrors `OBSERVE-12`'s honesty rule for Antigravity).

### D4 — Structured extraction v2 (SELFCAP-04)

Replace `summarize()`. Deterministic-first, from JSONL structure rather than prose:

- **decisions** — assistant turns containing decision markers, plus any `## Decision` / `Decided:` headers
- **outcomes / verification** — test/build/lint invocations and their exit results from tool-call records
- **errors** — non-zero exits, stack traces, and the tool call that produced them
- **commands** — Bash tool inputs, secrets-redacted
- **files** — Edit/Write targets and diff stats
- **entities** — repo, branch, project, referenced issue/PR ids

LLM assist is permitted **only** to write the human-readable summary line, only where depth policy allows, and never to invent any of the structured fields above. Redaction runs before extraction, not after. Output populates the rich fields `captureCodingAgentSession` already accepts.

### D5 — Scheduling (SELFCAP-05)

Installer emits a platform-appropriate unit (launchd plist on macOS, systemd timer on Linux, cron fallback) running the sidecar on an interval, plus a heartbeat row so `listObserveHarnessHealth` can show last-run, volume, and error count per harness. A stale heartbeat surfaces as a NOC Attention item (Phase 195 consumes it).

## Implementation Steps

1. `impact()` on `captureCodingAgentSession` and `authorizeRegistryWrite` before touching either.
2. Add agent-key auth + scoping + rate limit to `app/api/agent-memory/capture/route.ts`; add tests proving an agent cannot capture as another agent, and that depth policy holds for agent callers.
3. Write `scripts/hooks/memroos-memory-brief.sh` and `scripts/hooks/memroos-capture-gate.sh` to the D2 contract, with bounded timeouts and log-only diagnostics.
4. Extend `scripts/install-agent-integrations.sh` to install both hooks per target's hook mechanism; keep idempotence; add an uninstall path (`OBSERVE-05` parity).
5. Extend the maturity matrix + drift gate for hook coverage (D3).
6. Rewrite `summarize()` in `scripts/run-observe-sidecar.mjs` as the D4 extractor, with fixture-based unit tests over recorded JSONL from each Wave-1 harness.
7. Add the scheduler unit + heartbeat; wire into `listObserveHarnessHealth`.
8. Full verification.

Assert (a) the brief appears at session start without being asked and is ≤600 tokens, (b) ending the session produces one `agent_memory_candidates` row with non-empty decisions/outcomes/files — **not** a 240-char blob, (c) killing the MemRoOS server mid-session degrades to a receipt and does not block or hang the session.

## Risks

- **Hook protocol breakage.** A malformed hook can wedge a harness's startup. Mitigate with strict timeouts, no stdout pollution, and a documented one-line disable (`MEMROOS_HOOKS=0`).
- **Capture spam.** Per-session hooks plus a scheduled sidecar can double-write. `captureHash` dedup already exists — assert it in tests for the hook+sidecar overlap case specifically.
- **Extraction over-reach.** Pulling command history risks capturing secrets. Redaction must run before extraction; add a test with a planted fake credential asserting it never reaches the candidate row.
- **Installer blast radius.** It writes to 13+ targets in the operator's home. Add a `--dry-run` and land hooks behind an opt-out before enabling by default.
