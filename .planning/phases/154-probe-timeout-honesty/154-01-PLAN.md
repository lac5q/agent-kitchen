# Phase 154 — Probe Timeout Honesty

**Created:** 2026-07-15T20:45:27Z  
**Updated:** 2026-07-15T20:45:27Z  
**Version:** 2026-07-15.1  
**Requirement:** GATE-RESILE-01  
**Milestone:** v8.12 MemRoOS MCP Memory Gate Resilience (Codex)

## Goal

Raise the Mem0 `/health` probe used by `checkVectorHealth` / `/api/memory/health` from **3s to 15s** default, with `MEM0_HEALTH_TIMEOUT_MS` override, so slow-but-healthy Qdrant Cloud health responses (9–31s) are not reported as `vector=down`.

## Scope

- `apps/memroos/src/lib/memory/backends.ts` — extract `mem0HealthTimeoutMs()` mirroring `memorySearchTimeoutMs()`; use it in `_checkVectorHealthDirect`.
- Tests under `apps/memroos/src/lib/memory/__tests__/backends-health-timeout.test.ts` (new).
- Document env in relevant docs or `.env` examples if a memory env section exists (optional, minimal).

## Non-goals

- Changing strict gate allow-lists
- Changing search timeout (`MEMROOS_MEMORY_SEARCH_TIMEOUT_MS`)
- Reworking `memory-inventory.ts` (separate surface; out of this phase unless trivial)

## Tasks

1. Add `mem0HealthTimeoutMs()` reading `MEM0_HEALTH_TIMEOUT_MS` with default `15_000`, invalid → default.
2. Replace `timeoutSignal(3000)` in `_checkVectorHealthDirect` with `timeoutSignal(mem0HealthTimeoutMs())`.
3. On timeout/abort, keep status `down` but ensure detail reflects timeout (existing Error.message path).
4. Unit tests:
   - default resolves to 15000
   - env override works
   - invalid/zero/negative falls back to 15000
   - mocked fetch aborted at short timeout yields `status: "down"` with timeout-ish detail when AbortError thrown
