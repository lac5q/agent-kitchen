## Goal

Make a fresh `origin/main` clone of MemRoOS support the documented `install.sh --local`
path out of the box, without depending on host-specific path repairs or
cherry-picking a preserved local-profile branch. Drop `/Users/yourname/...` sample
paths from runtime config. Wire Agents and APO so they report truthful
`/api/health` after a clean install. Add a destructive-safe reinstall regression.
Triage `npm audit --omit=dev` findings.

## Sub-IDs (acceptance criteria)

### INSTALL-REPRO-01 — Restore canonical local installer profile
- A fresh `git clone https://github.com/lac5q/memroos.git` followed by
  `install.sh --local` builds and starts the local self-hosted stack
  (memroos + mem0 + Neo4j + Ollama + orchestration).
- `docker-compose.local.yml` exists in the repo at clone time.
- `install.sh` accepts `--local`, defaults `MEMROOS_COMPOSE_FILE` to
  `docker-compose.local.yml`, and the menu offers Local as option 1.
- README and `docs/install-profiles.md` document the local stack.

### INSTALL-REPRO-02 — Make runtime paths portable
- `grep -rn "/Users/yourname\|/home/yourname" '*.yml' install.sh .env.example apps/memroos`
  returns zero hits in runtime configuration. Documentation hits
  (`.planning/ROADMAP.md`, phase summaries, `.githooks/pre-commit`,
  `.github/workflows/secret-guard.yml`) are explicitly allowed.
- `.env.example` uses `${HOME}`-anchored defaults that Docker Compose
  expands when reading `.env` (verified via `docker compose config`).
- `install.sh` generates `.env` with shell expansion of `${HOME}` (uses
  `envsubst` if installed, otherwise a POSIX-portable shell loop).

### INSTALL-REPRO-03 — Wire Agents and APO intentionally
- `docker-compose.local.yml` passes `AGENT_CONFIGS_PATH` and
  `APO_PROPOSALS_PATH` to the app container.
- An independent bind mount for Agents (`/agent-configs`) is available when
  `AGENT_CONFIGS_HOST_PATH` is set; the standard subdir layout works
  without setting it.
- `docker compose -f docker-compose.local.yml exec memroos printenv AGENT_CONFIGS_PATH`
  returns a path that exists inside the container.

### INSTALL-REPRO-04 — Fix production typecheck without masking configs
- `apps/memroos/tsconfig.json` excludes only `**/vitest*.config.ts`
  (the narrowest possible exclusion that lets `npm run build` succeed
  when production Docker omits devDependencies).
- `next.config.ts`, `playwright.config.ts`, `postcss.config.mjs`,
  `eslint.config.mjs` remain typechecked.
- Verified: `npm run build --workspace apps/memroos` exits 0 with this
  exclusion alone.

### INSTALL-REPRO-05 — Destructive-safe reinstall regression coverage
- A regression script exercises: clean install, `.env` backup, named-volume
  preservation across reinstall, secrets mode 600, HTTP smoke checks on all
  five core services, second idempotent `install.sh` run exits 0.
- Designed to run in CI (lint-able) and on a disposable host.
- Wired into `.github/workflows/install-regression.yml`.

### INSTALL-REPRO-06 — Production dependency advisory triage
- `npm audit --omit=dev` baseline captured at the lockfile used for
  `origin/main` (4 high, 6 moderate, 2 low, 0 critical).
- Every finding has a ticket ID and reproduction command recorded in
  `.planning/phases/177-.../npm-audit-triage.md`.
- Zero untriaged high or critical findings before closeout.
- **No blind** `npm audit fix --force` is permitted.
