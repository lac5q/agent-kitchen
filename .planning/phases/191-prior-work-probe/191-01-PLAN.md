## Objective

Give an agent one cheap call that answers the question an employee actually has at a task boundary: *is there already work on this topic?* Phase 118 built the entire deterministic kernel to answer that and then left it with no live caller. This phase connects it and, in doing so, puts the first real data into `retrievalBeforeWorkRate`.

## Baseline (audited 2026-07-26)

- Two complete implementations exist. `apps/memroos/src/lib/recollection-policy.ts` (449 lines) exports `planRecollectionQueries`, `decideRecollection`, `scoreRecollectionCandidate`, `assembleRecollectionContextPack`, and is the canonical home of `BeliefStage` (re-exported by `lib/belief/types.ts:11`). `apps/memroos/src/lib/gsd/proactive-recollection.ts` (611 lines) is richer: `evaluateRecollectionTrigger`, `rankRecollectionCandidates`, a wider trigger vocabulary (`source_changed`, `operator_reask`, `rediscovered_fact_risk`, `final_answer_citation_gap`), and `telemetryFor()` emitting `efftel04RediscoveredFactGuard`.
- Neither is reachable. The only runtime wiring is `buildContextInjection()` at `lib/agent-runtime/memory-client.ts:227`, which has **zero production callers** — nothing under `app/api/` imports that module.
- Receipts already have a home: `lib/memory-trace-observability.ts` defines `RecollectionTraceReceipt`; `recordMemoryTrace()` persists it into `agent_memory_traces.causal_path_json` and emits it on the `retrieval_trace` efficiency event. The NOC read model already aggregates it (`app/api/operations/noc/route.ts:472-600`) and `components/operations/efficiency-signals.tsx` renders it.
- The write path is operator-gated: `POST /api/agent-memory/traces` uses `authorizeRegistryWrite` (`lib/operator-auth.ts:35`), which accepts `x-memroos-operator-key` only and rejects agent API keys.
- `GET /api/agent-context` **does** accept agent keys via `authenticateAgentHeaders`, but `buildAgentContextPacket()` (`lib/agent-context-packet.ts:509-710`) requires a `goal_id` and sources `memories[]` from a single SQL filter over `agent_memory_candidates` on `metadata_json.goalId/taskId` (`:535-549`) — no semantic search, so a fresh session on a topic gets an empty array.

## Scope

- Consolidate the two kernels into one module; delete the loser.
- Add a governed, agent-authenticated `POST /api/memory/prior-work` returning a pointer-sized digest.
- Expose it as MCP tool `memory_prior_work` in `CORE_TOOLS`, with the trigger contract in the tool description.
- Emit `retrieval_trace` receipts for both served and skipped probes through an agent-reachable path.
- Give `/api/agent-context` topic-based recall and an MCP wrapper.

## Non-Goals

- No new memory backend; no mem0/Qdrant/Neo4j/SQLite replacement.
- No raw memory payloads in the probe response — digest only.
- No LLM-only trigger decision; any LLM assist must produce typed evidence a deterministic policy consumes.
- No cross-project recall without an explicit allowlist and policy proof.
- No new ranking algorithm — reuse Phase 118 scoring as-is.
- No session hooks (Phase 192) and no skills (Phase 194).

## Design Contract

### D1 — Module consolidation (PRIORWORK-01)

Target `apps/memroos/src/lib/memory/recollection/` with `policy.ts`, `queries.ts`, `ranking.ts`, `context-pack.ts`, `types.ts`. Keep the `gsd/proactive-recollection.ts` trigger vocabulary and EFFTEL-04 guard; keep `recollection-policy.ts`'s `BeliefStage` export path stable so `lib/belief/types.ts` does not break. Use call-graph-aware `rename` (never find-and-replace) per repo policy, and run `impact({target, direction:"upstream"})` on each exported symbol first. Delete the losing module in the same commit — no deprecation shim, since neither has production callers.

### D2 — Probe response shape (PRIORWORK-02)

Request:

```json
{
  "task": "add rate limiting to the onboarding route",
  "repo": "lac5q/memroos",
  "project": "memroos",
  "entities": ["onboarding", "rate limit"],
  "timing": "before_plan"
}
```

Served response — digest, never payload:

```json
{
  "decision": "search_required",
  "timing": "before_plan",
  "headline": "Related prior work exists: 3 items",
  "reasons": ["task_has_entity_match", "project_has_recent_handoff"],
  "items": [
    {
      "id": "mem_01H...",
      "title": "Onboarding token signature mismatch RCA",
      "one_liner": "403 vs 401 contract; secret must match MEMROOS_ONBOARDING_SECRET",
      "belief_stage": "gold_operational_truth",
      "age_days": 8,
      "salience": 0.81,
      "fetch_ref": "memory://mem_01H..."
    }
  ],
  "tiers_searched": ["episodic", "vector", "graph"],
  "truncated": false
}
```

Skipped response is equally a receipt:

```json
{
  "decision": "search_skipped",
  "timing": "before_plan",
  "headline": "No prior-work search ran",
  "reasons": ["no_stable_entities", "local_formatting_task"],
  "skipReason": "Task is a mechanical format pass with no recall dependency.",
  "items": [],
  "tiers_searched": []
}
```

Hard budget: `items` ≤ 5, each `one_liner` ≤ 140 chars, total serialized response ≤ 2 KB. `truncated: true` when candidates were dropped for budget — never silently.

### D3 — Failure posture

Recall **fails open**. Backend timeout, unhealthy tier, or policy engine error returns `decision: "search_failed"` with a reason and an empty `items` array, and the agent proceeds. A degraded brain must never block work. The failure still emits a `retrieval_trace` receipt so the miss is measurable. Write-path policy checks remain fail-closed (unchanged).

### D4 — Auth

`authenticateAgentHeaders` (the path `/api/agent-context` already uses). Scope every probe to the calling agent's authorized projects/spaces; reuse the Phase 76 retrieval-authorization gate. Rate-limit per agent key. Never widen scope because the task text names another project.

### D5 — Tool description as contract (PRIORWORK-03)

The MCP tool description is the one injection surface always in context at ~50 tokens, so it carries the trigger contract:

> Call at the start of any task, when the topic shifts, when you hit an unexpected error, or before answering "have we done this before?" Returns a short digest of prior work — titles and fetch refs, not content. Cheap: call it rather than guessing.

### D6 — Receipts (PRIORWORK-04)

Route probe outcomes through the existing `recordMemoryTrace()` so `agent_memory_traces.causal_path_json` and the `retrieval_trace` efficiency event are both populated. Do **not** loosen `POST /api/agent-memory/traces` to agent keys; emit server-side from inside the probe handler, which is already agent-authenticated. Receipts carry decision, timing, reason codes, injected/ignored ids, score components, belief-stage counts, authorization result — and no raw memory content.

## Implementation Steps

1. Run `impact()` on `decideRecollection`, `planRecollectionQueries`, `scoreRecollectionCandidate`, `assembleRecollectionContextPack`, `evaluateRecollectionTrigger`, `rankRecollectionCandidates`, and `BeliefStage`; record the blast radius in this plan's Progress before editing.
2. Consolidate into `lib/memory/recollection/`; port the gsd trigger vocabulary and EFFTEL-04 guard; delete the losing module. Port both existing test suites and keep every case green.
3. Add `app/api/memory/prior-work/route.ts`: agent auth, rate limit, authorization scoping, kernel call, digest assembly with the D2 budget, D3 fail-open behavior.
4. Emit `retrieval_trace` via `recordMemoryTrace()` for served, skipped, and failed probes.
5. Add `memory_prior_work` to `services/knowledge-mcp/knowledge_system/mcp_server.py` and to `CORE_TOOLS` in `capabilities.py:13`, with the D5 description.
6. Extend `buildAgentContextPacket()` so the `memories` section falls back to topic recall through the recollection module when no `goal_id` is supplied; keep the existing metadata-filter path when one is.
7. Add an MCP wrapper for the context packet so agents stop needing `curl` / `scripts/show-agent-context-packet.mjs`.
8. Add route + kernel tests, then run the full verification list.

## Risks

- **Consolidation regression.** Two kernels, one survivor, and `BeliefStage` is imported elsewhere. Mitigate with `impact()` first, `rename` over find-and-replace, and porting both test suites before deleting anything.
- **Probe becomes expensive.** If the kernel fans out to every tier on every call, agents will feel the latency and stop calling it. Enforce the existing `MAX_RECOLLECTION_QUERY_LIMIT` and add a p95 latency assertion to the route test.
- **Digest too thin to be useful.** If `one_liner` is generated poorly, agents ignore results. Prefer stored titles/summaries over generation; measure via Phase 195 usefulness feedback.
- **Phase 189 collision.** LIBNORM-02 plans the same file move. Whichever lands first owns the move; the other rebases. Note the decision in both plans.
