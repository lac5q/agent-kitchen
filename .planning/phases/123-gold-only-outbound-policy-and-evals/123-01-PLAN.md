# 123-01 Plan: Gold-Only Outbound Policy + Promotion Evals

## Objective

Restrict outbound-facing generation paths (outreach drafts, CRM writeback, published docs) to **gold-only** claims via a policy flag, force silver claims to carry an inline caveat, and exclude bronze except as cited evidence. Then extend the Phase 118 recall evals into a promotion eval suite that proves unsupported candidate claims never surface as operational truth, contradicted gold demotes within one cycle, and every injected memory carries its belief stage in the receipt.

Depends on Phase 122 (promotion machinery must exist before outbound can gate on it).

## Scope

- Add a policy flag (`BELIEF_OUTBOUND_GOLD_ONLY`, default on) that outbound paths check.
- Provide a `filterOutboundClaims(claims, policy)` helper that returns gold claims as-is, silver claims with an inline caveat marker, and drops bronze (or returns it only under a `citation: true` mode).
- Wire the filter into the outbound-facing surfaces that exist today.
- Extend `evals/memory-recall/cases.json` with promotion/regression cases.
- Add a promotion eval runner that asserts the BELIEF-05 invariants.
- Run the promotion eval in CI alongside the existing recall canary.

## Non-Goals

- No changing the recollection context-pack path itself (that stays read-only over belief stage).
- No new outbound channel integrations (CRM/email/publish adapters are later milestones).
- No LLM-based caveat generation — the caveat is a deterministic marker string.
- No raw sensitive content in eval fixtures.

## Existing surfaces this builds on (verified 2026-07-06)

- **`apps/memroos/src/lib/recollection-policy.ts`** — `relianceFor(stage)` already maps gold→`direct_truth`, silver→`caveated_claim`, bronze→`source_evidence_only`. Reuse this mapping.
- **`apps/memroos/src/lib/belief/`** — NEW from Phase 122 (promotion, config, types).
- **`evals/memory-recall/cases.json`** + `runMemoryRecallEvalSuite` — Phase 118 eval harness; `MemoryRecallEvalCase` supports `avoidMemoryIds`/`avoidFacts` for negative fixtures.
- **`apps/memroos/src/lib/__tests__/memory-recall-canary-ci.test.ts`** — the CI canary pattern (`:memory:` DB + gold recall cases + threshold assertions).
- **`.github/workflows/ci.yml`** — already has a `recall-canary` job; add a `promotion-eval` job next to it.
- **Outbound surfaces today**: search for where claims/memories leave MemRoOS — dispatch evidence, task evidence bundles (`task_evidence_bundles.memories`/`sources` buckets), and any `/api/dispatch` response shaping. The Phase 122 review noted these as the realistic outbound chokepoints.

## Design Contract

### Outbound policy config

```ts
// apps/memroos/src/lib/belief/outbound-policy.ts (NEW)
export interface OutboundPolicy {
  goldOnly: boolean;        // default true, env BELIEF_OUTBOUND_GOLD_ONLY
  silverCaveat: string;     // default "[unverified claim — pending review]"
  bronzeAsCitationOnly: boolean; // default true
}
export function loadOutboundPolicy(): OutboundPolicy { /* env-driven, defaults above */ }
```

### `filterOutboundClaims`

```ts
export type FilteredClaim =
  | { stage: 'gold'; claim: Claim; caveat: null }
  | { stage: 'silver'; claim: Claim; caveat: string }
  | { stage: 'bronze'; claim: Claim; citationOnly: true };

export function filterOutboundClaims(
  claims: Claim[],
  policy: OutboundPolicy,
  opts?: { citationMode?: boolean }
): { emitted: FilteredClaim[]; dropped: Claim[]; receipts: OutboundReceipt[] } {
  // gold always emits; silver emits with caveat when goldOnly=false, else dropped+receipt;
  // bronze dropped unless citationMode=true (then emits as citationOnly)
  // every dropped/emitted decision produces a receipt with stage + reason + claim hash (no raw content)
}
```

### Wiring points

1. **Dispatch evidence** (`buildSkillEvidence` and any memory evidence shaping) — route outbound memory claims through `filterOutboundClaims`.
2. **Task evidence bundles** — the `memories`/`sources` JSON buckets tag each item with its filtered stage + caveat.
3. **A new outbound receipt type** in `efficiency_events` (`event_type = 'outbound_claim_filter'`) so NOC can see how many claims were caveated/dropped — mirrors the Phase 117/118 telemetry pattern.

### Promotion eval suite (BELIEF-05)

New file `evals/belief/cases.json` + runner `runBeliefPromotionEvalSuite`:

| Case | Asserts |
|------|---------|
| `unsupported_silver_never_truth` | A silver claim with a failed check is never returned as `direct_truth` reliance. |
| `contradicted_gold_demotes_in_one_cycle` | A gold claim contradicted by a new admission demotes within one promotion cycle (≤ 1 run). |
| `receipt_exposes_stage` | Every injected memory's receipt carries a non-null `beliefStage`. |
| `high_stakes_blocked_until_review` | A pricing claim stays out of gold-only outbound until review resolves. |
| `bronze_citation_only` | Bronze appears only when `citationMode=true`, else dropped with a receipt. |

CI: new `promotion-eval` job runs `npm run check:belief-eval` against `:memory:` DB, fails on any invariant regression. Sits next to `recall-canary` in `ci.yml`.
