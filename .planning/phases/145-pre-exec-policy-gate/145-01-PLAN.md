# Phase 145 Plan 01 — Pre-Execution Policy Gate (OPA/Rego)

**Phase:** 145  
**Milestone:** v8.5  
**Requirements:** FLEET-13..16  
**Status:** potential plan  

## Goal

Add a pre-execution policy evaluation at the adapter boundary so governance is not only post-hoc audit. Prefer local OSS (OPA/Rego or in-repo policy engine already used by POLGOV).

## Tasks

1. Define policy input shape: actor, agent id, runtime, tool/action, purpose, labels, budget status
2. Wire gate **before** tool execution on at least T1 adapters (Hermes path first)
3. Emit allow/deny receipt into audit + run ledger (reuse POLGOV receipt shape if possible)
4. Regression fixtures: deny destructive action without approval; allow memory read when labeled; MEMSEC-08 still green
5. Shadow mode optional for first ship (log would-deny without blocking) then enforce

## Success criteria

1. At least one T1 runtime has pre-exec gate on the tool path
2. Deny produces operator-visible receipt with policy version + reason
3. No bypass for headless runs (fail closed)

## Verification

- Unit tests for policy cases
- Integration smoke: denied tool does not execute
