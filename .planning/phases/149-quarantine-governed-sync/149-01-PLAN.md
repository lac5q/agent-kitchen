# Phase 149 Plan 01 — Quarantine Lane + Governed Auto-Sync

**Phase:** 149
**Milestone:** v8.6
**Requirements:** SKILLTRUST-03, SKILLTRUST-04
**Status:** potential plan

## Goal

No imported/marketplace skill goes directly to `enabled`. All imports run a quarantine lane (scanner pass + sandboxed eval + operator approval). Cross-harness skill changes arrive as import proposals with diffs, not silent updates. Version pinning per agent with one-step rollback.

## Tasks

1. Add `quarantine_status` column to `skill_registry` (TEXT: 'none'|'pending'|'scanner_passed'|'eval_passed'|'approved'|'rejected'). Default 'pending' for new imports/marketplace entries; 'none' for operator-created skills.
2. Quarantine flow: import → scanner pass (reuse `content-scanner.ts`) → sandboxed eval (reuse SkillForge eval gate minimal mode) → operator approval → enable. No skip path.
3. Add `skill_import_proposals` table: detected skill changes from Claude Code/Codex/Hermes/OpenCode dirs arrive as proposals with diff, source harness, timestamp, status (pending/approved/rejected).
4. Add `skill_version_pins` table: per-agent version pin with one-step rollback (restore prior version + audit row).
5. Tests: quarantine flow (import → scanner → eval → approve → enable), rejection path, import proposal creation, version pin + rollback, MEMSEC-08 regression.

## Success criteria

1. No imported/marketplace skill reaches `enabled` without passing quarantine
2. Scanner rejection blocks enablement (fail-closed)
3. Cross-harness skill changes create import proposals (not silent updates)
4. Version pinning per agent works with one-step rollback
5. MEMSEC-08 regression corpus passes byte-identical
