# 130-01 Plan: Teams/Spaces + Knowledge-Repo Labels

## Objective

1. **TEAMSCALE-01**: Spaces (e.g. GTM, Product, Finance) with default labels, human+agent membership, and cross-space sharing rules; per-space recall with zero cross-space leakage.
2. **MSIQ-01**: knowledge_write validates frontmatter labels (sensitivity/authoritative/verified_at/expires_at) mirroring MEMSEC-02 vocabulary.
3. **MSIQ-02**: knowledge_search/read enforce label-aware authorization per requesting agent identity; default-open for unlabeled docs.
4. **MSIQ-03**: Ranking boosts authoritative docs and demotes expired ones; scheduled expired/unverified flag job.

## Existing surfaces (verified)

- `apps/memroos/src/lib/db-schema.ts` — has `tenants`, `users`, `user_roles`, `user_api_keys`, `team_invitations` tables. NO spaces table yet.
- `apps/memroos/src/lib/vault/types.ts` — VaultVisibility, VaultDomain, VaultSensitivity, VaultPolicy, VaultLabel.
- `apps/memroos/src/lib/policy/engine.ts` — Phase 128/129 engine with dimension rules (subject.team can gate by space).
- `apps/memroos/src/lib/memory/policy-gate.ts` — authorizeMemoryUse (unchanged).
- `services/knowledge-mcp/knowledge_system/store.py` — KnowledgeStore with tenant-scoped vault isolation, `_validate_frontmatter` (basic name/description check), `search` (simple text search, no ranking), `read_text`, `write_text`.
- `services/knowledge-mcp/knowledge_system/mcp_server.py` — `knowledge_write`, `knowledge_search`, `knowledge_read`, `knowledge_policy_check` MCP tools.

## Design

### TEAMSCALE-01: Spaces (TS side)

- `db-schema.ts`: add `spaces` table (id TEXT PK, tenant_id TEXT REFERENCES tenants(id), name TEXT, default_labels_json TEXT, created_at TEXT) + `space_members` table (space_id TEXT REFERENCES spaces(id), member_id TEXT, member_type TEXT CHECK('human'|'agent'), role TEXT, created_at TEXT, PK(space_id, member_id)).
- `apps/memroos/src/lib/space.ts`: NEW. `createSpace(db, {tenantId, name, defaultLabels})`, `addSpaceMember(db, {spaceId, memberId, memberType, role})`, `getSpacesForUser(db, userId)`, `getSpaceDefaultLabels(db, spaceId)`.
- Space-scoped recall: `filterBySpace(rows, spaceId)` — filter message rows by `project` column (which maps to space name). Verify zero cross-space leakage in tests.

### MSIQ-01: Knowledge frontmatter labels (Python side)

- `store.py`: extend `_validate_frontmatter` to also validate knowledge-label fields when present: `sensitivity` (public/internal/confidential/restricted), `authoritative` (boolean), `verified_at` (ISO date), `expires_at` (ISO date). Invalid values → reject the write. Missing labels → allowed (default-open for solo installs).
- New `_extract_labels(content: str) -> dict` helper to parse frontmatter labels from markdown.

### MSIQ-02: Label-aware authorization (Python side)

- `store.py`: in `search` and `read_text`, after getting results, filter by label-aware authorization:
  - If a doc has `sensitivity: restricted` or `sensitivity: confidential`, and the requesting agent is not an admin/operator, filter it out (or deny the read).
  - If `sensitivity` is absent or `public`/`internal`, allow (default-open).
  - Authorization results visible in the response (add `label_authorized: true/false` to search results and read responses).

### MSIQ-03: Ranking + scheduled flag (Python side)

- `store.py`: in `search`, after filtering, sort results with a ranking function:
  - `authoritative: true` docs get a boost (sorted first within same relevance).
  - `expires_at` past → demoted (sorted last) and flagged `expired: true`.
  - `verified_at` absent → flagged `unverified: true` but not demoted.
- Add `flag_expired_unverified()` method that scans all markdown files and returns a list of expired/unverified docs for the scheduled job.
