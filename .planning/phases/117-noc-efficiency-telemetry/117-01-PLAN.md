## Goal

Replace the five NOC efficiency "missing telemetry" placeholders with trace-level event sources so the dashboard can compute retrieval-before-work, same-source re-reads, raw-context token share, operator re-ask redundancy, and rediscovered-fact rate from real data.

## Non-Goals

- No new memory backend or retrieval pipeline.
- No changes to mem0, Qdrant, Neo4j, or SQLite memory tier ownership.
- No fabricated NOC values; empty event streams stay honest empty/degraded states.
- No LLM-only efficiency scoring; metrics are deterministic counts and ratios.
- No cross-tenant aggregation.

## Requirements

| ID | Requirement |
| --- | --- |
| EFFTEL-01 | Dispatch and context-pack assembly emit structured trace events with timestamp, agent id, retrieval query, source, token count, and whether the result was used in the first response. |
| EFFTEL-02 | Tool-call transcript capture records per-tool read events with source identifier and source hash so repeated reads can be counted within a task window. |
| EFFTEL-03 | Model-routing telemetry distinguishes raw-context ingest tokens from processed/cached tokens so raw-context token share is measurable. |
| EFFTEL-04 | Chat transcript and memory-hit correlation events link operator questions to prior memory hits so redundant re-asks can be counted. |
| EFFTEL-05 | Memory write events include source, first-seen timestamp, and dedup hash so rediscovered facts can be identified. |

## Implementation Slices

1. **Efficiency event store and typed writer**
   - Add an append-only `efficiency_events` table through the versioned SQLite migration runner.
   - Add `apps/memroos/src/lib/efficiency-telemetry.ts` with typed event payloads, `recordEfficiencyEvent`, and query helpers.
   - Test insert/query/filter behavior for all five event types and invalid event rejection.

2. **Retrieval-before-work trace**
   - Emit `retrieval_trace` events from the memory trace/context-pack seam.
   - Payload: `query`, `sources`, `tokensUsed`, `usedInFirstResponse`, and timing gate.
   - Test zero-candidate and used-in-first-response cases.

3. **Same-source re-read detection**
   - Emit `source_read` events from tool-read transcript capture.
   - Compute repeated source hashes per task window.
   - Test same-hash re-reads and different-hash non-repeats.

4. **Raw-context token ledger**
   - Emit `token_ledger` events from model-routing/token-accounting paths.
   - Compute raw context share as `rawContextTokens / totalTokens` with a zero-division guard.
   - Test normal and zero-token cases.

5. **Operator re-ask redundancy**
   - Emit `operator_question` events from chat/operator-message ingestion with memory-hit correlation.
   - Use deterministic MVP matching only; richer semantic matching belongs to later recollection work.
   - Test redundant and non-redundant questions.

6. **Rediscovered-fact provenance**
   - Emit `memory_write` events from memory write ingress with source, first-seen timestamp, dedup hash, and `isRediscovery`.
   - Flag rediscovery when the same tenant has an earlier matching dedup hash.
   - Test duplicate and unique write sequences.

7. **NOC API/UI read model**
   - Update `/api/operations/noc` to compute efficiency metrics from `efficiency_events`.
   - Keep honest empty/degraded status when one or more metric streams have no events.
   - Update the existing efficiency panel to render real values without inventing data.

## Data Contract

### `retrieval_trace`

```ts
{
  query: string;
  sources: string[];
  tokensUsed: number;
  usedInFirstResponse: boolean;
  timingGate: "before_plan" | "before_tool" | "before_final";
}
```

### `source_read`

```ts
{
  sourceId: string;
  sourceHash: string;
  toolId: string;
}
```

### `token_ledger`

```ts
{
  rawContextTokens: number;
  cachedTokens: number;
  totalTokens: number;
  modelId: string;
}
```

### `operator_question`

```ts
{
  questionText: string;
  memoryHits: string[];
  priorAnswerMatch: boolean;
}
```

### `memory_write`

```ts
{
  source: string;
  firstSeenAt: string;
  dedupHash: string;
  isRediscovery: boolean;
}
```

## Risks

- The event table must follow the Phase 115 versioned migration convention; test idempotency and future-version failure behavior.
- Hot-path write overhead may matter for retrieval/tool telemetry; keep inserts narrow and indexed by event type, task, and timestamp.
- Operator re-ask matching is intentionally conservative in this phase; avoid semantic claims until Phase 118 recollection receipts provide stronger evidence.
- Phase 118 depends on these event contracts; keep the payloads stable or record a migration note before recollection work consumes them.
