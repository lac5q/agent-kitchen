# Phase 199: Connector Memory Ingestion (CONNMEM-01..07)

**Phase ID:** 199
**Milestone:** v8.28 Connected Tools as Memory
**Date added:** 2026-07-27
**Status:** IN PROGRESS (CONNMEM-01..04 landed; 05..07 open)
**Depends on:** STORECON-03 (Ollama embeddings must be generating, or synced rows sit unembedded)

## Goal

Make every connected provider available as searchable MemRoOS memory.

Connecting a provider in Settings → Integrations stored a credential and
nothing else. MCP is pull-on-demand by design, so "Connected ✅" meant *an
agent can query Linear when asked* — not *your Linear workspace is
searchable*. This phase closes that gap for every provider with a live Nango
integration.

## The architectural decision, and why

**Connector content lands in `messages`, not a table of its own.**

`runEmbeddingCycle` selects `FROM messages`; `messages_fts` is an
external-content index over `messages`. A row written there is embedded and
full-text searchable with zero changes to either. A dedicated table would have
forked both pipelines. The table's own `UNIQUE(session_id, request_id)` then
gives idempotent re-sync for free — `session_id` is stable per connection,
`request_id` is the provider's object id — so no dedupe table and no content
hashing.

**One space per provider** is the isolation boundary. `space_members` decides
who can recall the content; `spaces.default_labels_json` decides whether it is
indexable at all. Both are data an operator can change, not literals in the
sync loop. Rows are owned by a synthetic `connector:<provider>` agent —
attributing them to the connecting human would conflate "Luis connected this"
with "Luis wrote this" and drop a shared workspace into one person's memory.

## Providers are not interchangeable — verified 2026-07-27

Probing the live providers found three structurally different shapes. This is
why the manifest is data rather than per-provider code:

| Provider | Transport | Response shape | Incremental | Pagination |
|---|---|---|---|---|
| Linear | MCP | `{issues:[...]}` | `updatedAt` ✅ | cursor + `hasNextPage` |
| Circleback | MCP | **bare array** | none | integer `pageIndex` |
| Notion | **REST** | `{results:[...]}` | none | `next_cursor`/`has_more` |

Nango's provider template is the discriminator: `auth_mode: MCP_OAUTH2` means
MCP, `OAUTH2` means REST.

## Sub-IDs (acceptance criteria)

### CONNMEM-01 — Ingestion core ✅ DONE

`lib/connectors/{manifest,store,mcp-client,sync-job}.ts`. Rows land in
`messages` with labels sourced from the space, never hardcoded. Schema 31→32
adds `connector_sync_state` via a real migration (a baseline-only CREATE TABLE
would never reach a DB already stamped at 31 — verified by upgrading a v31 DB).

### CONNMEM-02 — Multi-transport support ✅ DONE

MCP and REST in one loop; `resultKey: null` handles Circleback's bare array
(reading it through a key yields zero records *silently*, which is worse than
an error).

### CONNMEM-03 — Untrusted content is quarantined ✅ DONE

Every record passes `detectInjection` before becoming memory. A Linear issue
body can carry a forged tool directive or a leaked credential, and an agent
will later read this as context.

### CONNMEM-04 — Adversarial validation ✅ DONE

An independent validator pass confirmed five real defects, all now fixed and
regression-tested:

1. **`INSERT OR IGNORE` discarded every edit.** A rewritten issue conflicted on
   the unique constraint and was thrown away, so memory served the first-ever
   version forever — voiding the incremental fetch entirely. Now an upsert
   guarded on `excluded.timestamp > messages.timestamp`.
2. **Budget break advanced the high-water mark past unread records.** Records
   arrive newest-first; a mark derived from the processed prefix jumped the
   unread tail, which was then never requested again. Now gated on
   `pageComplete`.
3. **Hardcoded `updatedAt` timestamp.** Circleback has only `createdAt`, Notion
   `last_edited_time`; both collapsed onto the ingest date, corrupting recency
   ranking. Now `timestampField` per tool.
4. **One throwing provider starved every provider after it**, every cycle, in a
   stable iteration order. Now per-connection and per-tool boundaries, with
   `degradedProviders` making `degraded` actionable.
5. Manifest named a `notion-rest` integration that does not exist in Nango.

### CONNMEM-05 — Wire the job into startup ⬜ OPEN

`startConnectorJob()` exists but is **not called**. Deliberately: once running
it backfills at 200 rows / 15 min, each row costing an Ollama embedding on
oracle-1. **Gate:** disk headroom check on oracle-1 before enabling, same rule
as STORECON-03 — do not enable if it would drive free space under the
`memroos-disk-watch` warn threshold (6GB).

### CONNMEM-06 — Remaining providers ⬜ OPEN (BLOCKED)

Slack, Google Calendar, Google Drive, GitHub have Nango integrations but **no
live connection** — nothing to sync until someone connects them. Manifests
should be written when a connection exists to verify the response shape
against, not before: every shape assumption made without probing has so far
been wrong.

### CONNMEM-07 — Quarantine audit trail ⬜ OPEN

A quarantined record is currently dropped with no persisted trace. Combined
with the high-water mark, a flagged injection attempt becomes unreviewable.
Needs an audit row.

## Constraints

- No credential values in commits; secrets travel via `op read` to stdin.
- Labels always sourced from `spaces.default_labels_json`.
- Connector rows always carry a real `space_id` — `filterBySpace` falls back to
  matching `project` against the space *name*, so a null would risk a
  cross-space leak. `project` is namespaced `connector/<provider>` besides.
