# Phase 228 — Onboarding Rescue: fail-proof or fail-diagnosable

**Milestone:** v8.38 · **Requirements:** ONBRESCUE-01..05 · **Written:** 2026-08-04
**Source RCA:** STATE.md "Latest Position (2026-08-04)"; cordant `.health/e2e-adc486a5-claude-report.md`

## Baseline (audited 2026-08-04)

- `apps/memroos/src/lib/email/invite-email-draft.ts:21` — `"You're invited to MemRoOS (Cordant)."`
  hardcoded; every brain's invite claims Cordant.
- `apps/memroos/src/lib/agent/onboarding.ts` — `createAgentOnboardingToken` normalizes but never
  validates `memroosUrl`/`mcpUrl`; a corrupt base URL mints a corrupt (yet validly signed) token.
- Signature failures (`onboarding.ts:115`) return a bare string; no way to distinguish wrong-brain
  minting / key rotation / tampering.
- `scripts/verify-onboarding-deploy.sh` checks oracle only; no signing-secret assertion.
- `resolvePublicMemroosUrl` (`lib/http/public-base-url.ts`) silently falls back to forwarded-host
  when env is localhost (the oracle-1 misconfiguration).

## Steps

1. **ONBRESCUE-01** — `resolveWorkspaceName()` in `lib/env.ts` (or a small `lib/instance.ts`):
   `MEMROOS_WORKSPACE_NAME` → else capitalized first label of the public-base-URL hostname → else
   "MemRoOS". Thread through `buildInviteEmailDraft`/`buildInviteEmailHtml` (new options field,
   default resolved at call sites in `api/auth/invite/route.ts` + Team UI draft). Update
   `.env.example` + cordant/oracle deploy docs.
2. **ONBRESCUE-02** — `assertMintableUrl(raw)` in `lib/agent/onboarding.ts`: `new URL()` parse;
   reject commas, whitespace, credentials-in-URL; reject repeated-host patterns
   (`host.tld` appearing twice in hostname); require https for non-localhost. Called for both
   `memroosUrl` and `mcpUrl` in `createAgentOnboardingToken`. Throws typed `OnboardingMintError`;
   bootstrap/invite routes surface 500 with the reason (server misconfig, not client fault).
3. **ONBRESCUE-03** — `kid = sha256(signingSecret()).slice(0,8)` embedded in payload at mint;
   verify path compares and, on signature failure, returns
   `Invalid onboarding token signature (token kid <a>, server kid <b>)` when both are known.
   No secret material leaks (one-way, 8 hex chars). Tests: mint/verify round-trip, cross-secret
   mismatch message, tamper case.
4. **ONBRESCUE-04** — extend `scripts/verify-onboarding-deploy.sh`: iterate
   `https://memroos.epiloguecapital.com` + `https://memroos-cordant.epiloguecapital.com`
   (overridable via args); assert bad-token 403; warn loudly when
   `MEMROOS_ONBOARDING_SECRET` is unset host-side (best-effort informational section).
5. **ONBRESCUE-05** — in mint paths (`bootstrap`, `invite`): when `NODE_ENV=production` and the
   env candidates were all unset/localhost, write a NOC Attention item (existing attention
   producer pattern) naming the fallback host used; unit test with mocked env.

## Verification

- Unit: invite draft names workspace from env; mint rejects corrupt URLs; kid mismatch message;
  boot assertion attention item.
- Full fast suite + typecheck + lint green.
