# Phase 150 Plan 01 — Lifecycle States + Dependency View + Deprecation Warnings

**Phase:** 150
**Milestone:** v8.6
**Requirements:** SKILLTRUST-05
**Status:** potential plan

## Goal

Add skill lifecycle states (draft, enabled, deprecated, retired) with deprecation warnings surfaced to dependent agents, a dependency view showing which agents/workflows use which skill versions, and audit on every state change.

## Tasks

1. Add `lifecycle_state` column to `skill_registry` (TEXT: 'draft'|'enabled'|'deprecated'|'retired'). Default 'draft' for new entries; existing entries migrate to 'enabled' if dispatch_status='enabled', else 'draft'.
2. State transition functions: `transitionSkillState(db, skillId, newState, actorId, reason)` — validates allowed transitions (draft→enabled, enabled→deprecated, deprecated→retired, enabled→draft), writes audit row, fails closed on invalid transitions.
3. Deprecation warnings: when a skill is deprecated, dispatch returns a warning in the receipt; dependent agents see the warning in their context packet or NOC strip.
4. Dependency view: `getSkillDependencies(db, skillId)` returns which agents/workflows reference the skill (from dispatch log, skill_version_pins, agent config); `getSkillDependents(db, agentId)` returns which skills an agent uses.
5. Tests: state transitions (valid + invalid), deprecation warning in dispatch receipt, dependency view queries, audit on state change, MEMSEC-08 regression.

## Success criteria

1. Lifecycle states exist with valid transition enforcement
2. Deprecation warnings surface to dependent agents in dispatch receipts
3. Dependency view shows skill→agents and agent→skills relationships
4. Every state change writes an audit row
5. MEMSEC-08 regression corpus passes byte-identical
