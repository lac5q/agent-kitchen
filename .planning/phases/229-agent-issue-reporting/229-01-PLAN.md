# Phase 229 — Agent Issue Reporting: the channel that survives failure

**Milestone:** v8.38 · **Requirements:** AGENTREPORT-01..05 · **Written:** 2026-08-04
**Operator directive (2026-08-04):** "we need a way for agents to report back to memroos when any
problems occur … make sure there's an active communication channel for any issues."

## Design constraint (binding)

The reporting path rides the **weakest surviving credential**, not the strongest. In the Eric RCA
the agent had working MCP OAuth (`knowledge_write` succeeded) while every `MEMROOS_AGENT_API_KEY`
surface bounced. Therefore intake accepts agent-key auth **or** MCP OAuth session auth, and is
never gated on the agent key. It must not become a spam or exfil vector: rate-limited, size-capped,
secret-rejecting.

## Baseline (audited 2026-08-04)

- `agent_context_send`/`inbox` (Phase 107 bus) — agent-key-only; correct for inter-agent traffic,
  wrong as the *only* failure channel (chicken-and-egg proven in RCA).
- `.health/bug-reports/` git-commit convention — works but is host-local, invisible to NOC, and
  needs repo write access.
- NOC Attention items + audit chain exist (v8.18) — reuse, don't reinvent.

## Steps

1. **AGENTREPORT-01** — schema: `agent_issue_reports(id, reporter_kind CHECK(agent_key|oauth),
   reporter_id, agent_id NULL, severity CHECK(low|medium|high|critical), component, title, body,
   status CHECK(open|acked|resolved) DEFAULT open, created_at, acked_at NULL, resolved_at NULL,
   resolution_note NULL)` via the governed store chokepoint (Phase 188 pattern — no raw
   better-sqlite3 outside the allowlist). `POST /api/agent-report`: auth = `authenticateAgentHeaders`
   OR MCP-OAuth session introspection; rate limit (5/hour/principal, existing `auth/rate-limit.ts`);
   body caps (title 200, body 8k); secret-pattern rejection (`ak_[A-Za-z0-9_-]{20,}`, `SG\.`,
   `Bearer\s+[A-Za-z0-9._-]{20,}`, hex-64) with coach-back "strip credentials and resend".
   `GET /api/agent-report` (operator session): filter by status/severity/component.
2. **AGENTREPORT-02** — MCP tool `report_issue` registered in `CORE_TOOLS` next to
   `knowledge_health`; handler posts through the same intake path with OAuth identity fallback;
   description: "Report a problem with MemRoOS itself (broken tool, auth failure, timeout).
   Works even when other agent surfaces are down."
3. **AGENTREPORT-03** — NOC Attention producer for open reports (critical/high immediately, others
   aggregated); Team page badge with count; ack/resolve actions (operator role) each writing an
   audit entry (`agent_issue.acknowledged` / `agent_issue.resolved`).
4. **AGENTREPORT-04** — onboarding script template (`api/onboarding/script`): wrap each step; on
   4xx/5xx, POST `{component:"onboarding", severity:"high", step, httpStatus, errorBody(truncated),
   platform, tokenKid}` to `/api/agent-report` on the same host — auth-exempt **only** for
   `component=onboarding` posts carrying a syntactically valid (even if unverifiable) token kid,
   rate-limited by IP. Failed onboarding becomes server-visible without human email forwarding.
5. **AGENTREPORT-05** — contract propagation: AGENTS.md template section, orientation prompt line,
   memroos-troubleshooter skill update; `.health/bug-reports/` documented as last-resort fallback.
