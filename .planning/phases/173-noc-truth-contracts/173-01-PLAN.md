<objective>
Make the NOC data contract honest for a single operator. Add the smallest shared API fields needed for Attention and message-backed Agent Activity. Keep EFFTEL visible only as a known-unwired advanced capability.
</objective>

<files>
- `apps/memroos/src/app/api/operations/noc/route.ts` — extend the existing aggregate route with attention, freshness, and per-agent activity data.
- `apps/memroos/src/lib/api-client.ts` — type and expose the new NOC fields through the existing hook.
- `apps/memroos/src/components/operations/attention-panel.tsx` — render the severity/freshness/next-action queue using existing NOC primitives.
- Route/component tests listed above — prove day-1 source behavior and no-hive fallback.
</files>

<steps>
1. Start from `origin/main` in an isolated worktree. Read the current `OperationsNoc` response type, `noc/route.ts` queries, `useOperationsNoc`, and existing NOC tests.
2. Add one typed `attention` collection to the existing NOC response. Build it only from existing cron-health, HIL, security/escalation, and source-freshness data. Sort critical, warning, then info; include timestamp and existing route/action target when one exists.
3. Add a grouped message query for the selected window and workspace to return Agent Activity. Join/map agent identity only through existing columns; do not create a session table or capture pipeline.
4. Keep `useDelegations` or equivalent delegation data optional. Return delegation counts/details only when rows exist; message activity remains the base signal.
5. Add a deterministic source-state enum for `live`, `window_empty`, `no_history`, `stale_or_error`, and `known_unwired`. Mark EfficiencySignals/`efficiency_events` known-unwired until an EFFTEL producer is verified.
6. Add `AttentionPanel` with existing `Eyebrow`, `PillBtn`, and NOC theme primitives. Render an explicit all-clear state when no attention rows exist.
7. Add focused route and component tests: day-1 message-backed activity without hive rows; severity ordering; all-clear; known-unwired EfficiencySignals; stale/error stays distinct from no-history.
</steps>
