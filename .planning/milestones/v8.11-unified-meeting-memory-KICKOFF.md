## Architecture Decision

Federate meeting memory at **query time**. Do not merge private `data/context/` into git.
Harden meet-sync ingest (idempotent IDs, rich frontmatter, public provider templates, health),
then expose one agent-facing facade: MCP `memory_recall`.

### Existing Infrastructure

- `scripts/meet-sync/` — declarative multi-provider runner (ingest → QMD update → embed → status)
- Private operator config: `~/.memroos/meeting-sources.json` + `~/.memroos/integrations/`
- Per-provider QMD collections (`meet-recordings-circleback`, `-epilogue`, `-personal`, `-zoom`, …)
- MCP `knowledge_search` (KNOWLEDGE_ROOT literal) + vector workspace `qmd` search with `-c`
- `/api/memory/multi-search` — vector / graph / episodic tiers (no meeting QMD lane yet)

### What v8.11 Adds

1. **MEETREL-01..04** — Idempotent filenames by recording/meeting id; frontmatter
   (`calendar_title`, `share_url`, `meeting_id`, `source`); public `scripts/meet-sync/providers/`;
   `meet-sync --health`.
2. **URECALL-01..03** — Shared resolver across enabled meeting QMD collections + knowledge
   literal + mem0; MCP `memory_recall` as default meeting/memory tool; orientation prefers it
   over collection-aware `qmd -c` / naive `knowledge_search` for “find the meeting”.
3. **URECALL-04..06** — `/api/memory/multi-search` QMD meeting lane; docs +
   `collections.config.json` list private meeting collections; Monaco Circleback + Fathom
   Impromptu regressions via `memory_recall` without `-c`.

## Follow-up: MEETREL-FOLLOWUP-05 — Source-to-Index Evidence

Added July 16, 2026 after a Cordant meeting could not be located through the currently connected Circleback/Fathom sources and the Cordant Google Meet/Drive queries were blocked by insufficient OAuth scopes. Spark Desktop had captured the full transcript and direct QMD collection search retrieved it, but the unified MCP `memory_recall` facade returned no QMD result from that same `spark-recordings` collection.

This follow-up fixes two proven failure modes: unified-recall parity for Spark-indexed meetings, and false-healthy provider auth status. It must make each stage independently provable: provider presence, authorization, raw capture, project routing, QMD indexing, and unified recall. The final trace must distinguish `provider_absent`, `provider_auth_blocked`, `captured_unrouted`, `routed_unindexed`, `indexed_unrecalled`, and `recalled`, and must never treat an authorization failure as an empty successful sync.
