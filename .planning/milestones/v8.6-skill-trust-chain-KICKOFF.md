## Architecture Decision

Skill trust chain extends the existing skill_registry (Phase 72), content-scanner, SEAL proposal infrastructure, and SkillForge eval gate to create a full supply-chain trust model for skills.

### Existing Infrastructure

- `skill_registry` table: name, source_harness, risk_tier, dispatch_status (enabled/disabled/incomplete/review), completeness_pct, version, preconditions, allowed_tools, verification_checks, rollback_behavior, raw_body
- `skills/registry.ts`: SKILL.md parser, completeness scorer, normalizeRegistryEntry (fail-closed on incomplete)
- `dispatch/skill-lookup.ts`: lookupSkillContract (fail-closed on incomplete/disabled/review)
- `content-scanner.ts`: secrets/PII/injection pattern scanner
- `seal/`: SEAL proposal lifecycle (proposed → approved → applied → rolled_back)
- `skillforge/`: eval gate, operator approval, marketplace
- `skill_sync_log` table (Phase 93): basic sync tracking
- `skill_marketplace` table (Phase 92): publish/rate/discover

### What v8.6 Adds

1. **SKILLTRUST-01**: Enhanced contracts — add `evidence_examples` field to skill_registry; dispatch must fail-closed on incomplete contracts (already partially shipped via Phase 72 completeness gate; extend with evidence_examples)
2. **SKILLTRUST-02**: Content hashing + signing — add `content_hash`, `signature`, `signed_by`, `trust_level` columns; registry records provenance (author, source, signature); dispatch can be policy-restricted to signed skills above trust threshold
3. **SKILLTRUST-03**: Quarantine lane — imported/marketplace skills run scanner pass + sandboxed eval + operator approval before enablement; no direct-to-enabled imports
4. **SKILLTRUST-04**: Governed cross-harness auto-sync — detected skill changes in Claude Code/Codex/Hermes/OpenCode dirs arrive as import proposals with diffs; version pinning per agent with one-step rollback
5. **SKILLTRUST-05**: Lifecycle states (draft/enabled/deprecated/retired) with deprecation warnings surfaced to dependent agents, dependency view, audit on every state change

## Phase Decomposition

- **Phase 148**: SKILLTRUST-01 + SKILLTRUST-02 (enhanced contracts + content hashing/signing)
- **Phase 149**: SKILLTRUST-03 + SKILLTRUST-04 (quarantine lane + governed auto-sync)
- **Phase 150**: SKILLTRUST-05 (lifecycle states + dependency view + deprecation warnings)

## Hard Constraints

- MEMSEC-08 regression corpus must pass byte-identical
- Zero new npm dependencies
- Schema migration v10→v11 (additive, idempotent)
- Fail-closed defaults everywhere
- Receipts carry no raw sensitive payloads
