# Roadmap: Memroos v8.36 — Public / Private Repository Split

*Created: 2026-07-31*

## Status

Planned. Not started. **Contains a blocking action that applies immediately** (Phase 214,
criterion 1).

Triggered by the v8.32 identity work: `lac5q/memroos` is **PUBLIC**, and v8.32's roadmap is
a precise inventory of exploitable defects in a system running live on two hosts. Committing
it as-is publishes an attack guide.

### Measured repository state (2026-07-31)

| | |
|---|---|
| Repo | `lac5q/memroos` — **PUBLIC** |
| Public since | 2026-04-08 |
| History | 1,577 commits |
| Forks / stars | **1 fork**, 6 stars |
| `.planning/` | **tracked — 584 files, all public** |
| Secrets hygiene | `.env`, `.env.local`, `apps/memroos/.env.local` all correctly gitignored ✓ |
| Licensing | `LICENSE` + `COMMERCIAL-LICENSE.md` already present |

### The constraint that shapes every option

**Making a public repository private does not unpublish its history.** 1,577 commits have
been publicly available since April. There is 1 fork, which retains its own copy, and
GitHub's fork network can retain reachable objects independently of the parent's visibility.

So the goal is not "un-publish what happened." It is **"stop the exposure growing, and put
the product behind a boundary from here forward."** Any plan promising retroactive privacy
is lying.

### Chosen strategy (operator directive)

> "decouple public github repo from this product so that this version is not public,
> i want the public version to be left where it is."

That is **Strategy A: new private repo for the product; `lac5q/memroos` stays public, where
it is.** Rejected alternative — flipping the current repo to private and spinning out an OSS
subset — would break the existing public URL, the stars, and the fork relationship, while
still not retracting anything already published.

## Phase 214: Exposure Containment

**Goal:** Stop making it worse, today, before any migration work starts.

**Requirements:** REPOSPLIT-01..04

**Success Criteria:**

1. **BLOCKING, applies now: do not commit or push `.planning/milestones/v8.32-identity-access-ROADMAP.md`
   or the modified `.planning/ROADMAP.md` to `lac5q/memroos`.** v8.32 documents, with
   file:line precision: replayable onboarding tokens with no nonce check, an unscoped-token
   path that can register *any* agent id including trusted ones, a re-registration path that
   un-revokes revoked agents and mints fresh keys, and FK enforcement being off. Against
   hosts that are live. These files are currently **uncommitted** — that is the good news,
   and it is reversible only while it stays true.
2. Audit what is *already* public in `.planning/` (584 files) for the same class of content:
   live vulnerability descriptions, host names, internal topology, credential locations.
   Produce an inventory with a keep / redact / remove decision per finding.
3. Scan the full 1,577-commit history for committed secrets (`gitleaks` or `trufflehog`).
   Env files are correctly ignored today, but that says nothing about the last 15 months.
   **Any hit is rotated, not just deleted** — deletion from history does not invalidate a
   leaked credential, and the fork may retain it.
4. Check the single fork: whether it is current, whose it is, and what it already carries.

**Note:** criterion 1 is the entire reason this milestone jumped the queue. Everything else
here can move at a normal pace.

## Phase 215: Boundary Definition

**Goal:** A written, defensible line between the open-source project and the commercial
product — decided deliberately, not by whatever happened to be in the tree.

**Requirements:** REPOSPLIT-05..08

**Success Criteria:**
1. Every top-level area is classified **OSS** / **product** / **internal-only**. At minimum:
   `apps/memroos`, `services/knowledge-mcp`, `packages/sdk-ts`, `packages/sdk-py`,
   `agents/`, `docs/`, `scripts/`, `.planning/`, `evals/`.
2. **`.planning/` is classified internal-only** unless there is an affirmative reason
   otherwise. It is planning exhaust: roadmaps, learnings, retrospectives, and — as v8.32
   shows — security analysis. It is the highest-risk directory in the repo and the least
   valuable to outside readers.
3. The existing `LICENSE` / `COMMERCIAL-LICENSE.md` split is reconciled with the new
   boundary, so the licence text matches where code actually lives.
4. Customer-specific material (Cordant configuration, tenant references, deployment
   topology, host names) is classified internal-only without exception.

## Phase 216: Private Repository Standup

**Goal:** The product has a private home.

**Requirements:** REPOSPLIT-09..12

**Success Criteria:**
1. A new private repo exists (e.g. `lac5q/memroos-product`), owned appropriately, with
   branch protection and access limited to who actually needs it.
2. **A history decision is made explicitly and recorded.** Two honest options:
   - *Fresh history* (recommended): squash to a single initial commit. Nothing carries
     forward that was already public anyway, and the new repo starts clean. Cost: loses
     `git blame` lineage.
   - *Full history copy*: preserves blame, but imports 1,577 commits that are already public
     into the private repo — offering no privacy benefit for that content while making
     secret-scanning remediation permanently harder.
3. Whichever is chosen, the private repo passes a secret scan **before** the first push.
4. `.planning/` moves to the private repo with its full history intact — the planning record
   is genuinely valuable internally, just not publicly.

## Phase 217: Toolchain Rewiring

**Goal:** Nothing silently keeps pointing at the public repo.

**Requirements:** REPOSPLIT-13..16

**Success Criteria:**
1. Every hardcoded `lac5q/memroos` reference is found and updated. Known categories from
   this codebase: `agents/AGENTS_TEMPLATE.md` (the canonical agent directive, which names
   the repo and installer URLs), `scripts/install-agent-integrations.sh`,
   `scripts/setup-codex-cloud.sh`, `scripts/setup-cursor-cloud.sh`, `.cursor/environment.json`,
   `CLAUDE.md` / `AGENTS.md` source links.
2. CI, deploy paths, and the Cloudflare/oracle-1 + cordant-hermes-01 pull paths are rewired
   and **verified by an actual deploy**, not by inspection.
3. Cloud agent environments (Codex Cloud, Cursor Cloud, Claude Code Remote) can still clone
   what they need — these authenticate differently against a private repo, and this is the
   most likely thing to break silently.
4. The MemroOS MCP installer flow still converges on every host after the move.

## Phase 218: Public Repository Disposition

**Goal:** Decide what `lac5q/memroos` *is* now, rather than leaving it ambiguous.

**Requirements:** REPOSPLIT-17..19

**Success Criteria:**
1. An explicit decision, recorded: does the public repo continue as a maintained OSS core,
   or is it frozen with a pointer to the product?
2. Content classified internal-only in Phase 215 is removed from the public repo going
   forward, with the honest caveat that removal is not retraction — history and the fork
   retain it.
3. The public README states plainly what the repo is and is not, so the 6 stargazers and 1
   forker are not misled by a repo that quietly stopped being the real thing.

---

## Phase 219: Leakage Guardrails

**Goal:** Make "we published our vulnerability roadmap" structurally impossible, not merely
unlikely.

**Requirements:** REPOSPLIT-20..23

**Success Criteria:**
1. A pre-push hook or CI check on any public repo that blocks commits touching
   internal-only paths.
2. Secret scanning runs in CI on every push, not as a one-time Phase 214 audit.
3. A short written rule — in `CLAUDE.md` / `AGENTS.md` so every agent inherits it — stating
   that security analysis, vulnerability inventories, host topology, and customer
   configuration never go to a public repo. **This session is the worked example:** an agent
   wrote a precise exploit inventory into a tracked planning directory without noticing the
   repo was public. The rule needs to be in the file agents actually read.
4. Repo visibility is asserted in CI, so a future accidental flip to public fails loudly.
