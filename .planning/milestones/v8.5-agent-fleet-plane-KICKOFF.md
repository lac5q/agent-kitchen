# v8.5 Agent Fleet Plane — Milestone Kickoff

*Created: 2026-07-08*
*Status: Phase 144 complete / locked; Phase 145 next (potential plan)*
*Source thread: Discord #devops — "Agent fleet control tooling research" (2026-07-08)*

## Goal

Make **MemroOS the top-layer agent fleet plane** that directly manages agents across all runtimes (Hermes, Claude Code, Codex, OpenClaw, Cursor, Qwen, Gemini, ZCode, OpenCode), **pairs with LangGraph as a peer orchestration runtime** (not a competing control plane), and treats **Paperclip as a parallel product plane / tenant** — not the fleet plane above everything.

## Architecture decision (locked for this milestone)

```
MemroOS  → TOP LAYER (registry, memory, governance, A2A, NOC, fleet)
LangGraph → PEER inside MemroOS (stateful graphs, checkpoints, HIL)
Paperclip → PARALLEL TENANT (own company, budgets, board; subscribes via adapter)
```

**Do not** adopt LangGraph-as-control-plane, Archestra-as-top-layer, CrewAI ACP (cloud-only), or any project named "Gardner" (does not exist as OSS agent orchestrator).

## Desired outcomes

| # | Outcome | Why it matters |
|---|---------|----------------|
| O1 | Architecture decision is durable in GSD + knowledge | Operators stop re-litigating "Paperclip vs MemroOS vs LangGraph" |
| O2 | Runtime adapter maturity is explicit (T1/T2/T3) | Diagrams stop lying that all nine install targets are equal |
| O3 | LangGraph peer contract is pinned | Checkpoint/HIL ownership split is no longer tribal knowledge |
| O4 | Pre-execution policy gate at adapter boundary | Governance is OS-level, not audit-after-the-fact only |
| O5 | Paperclip is a first-class MemroOS tenant | Cost/budget stays in Paperclip; fleet registry stays in MemroOS |
| O6 | Secrets + HA path for kernel + checkpoints | Fleet can leave single-laptop assumption safely |
| O7 | Independent second-opinion validation of architecture | Close MiniMax self-validation gap before binding clients |
